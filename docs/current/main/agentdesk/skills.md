# スキル

スキルは、**このデスクができること、すなわち業務手順**です。人の窓口に置かれた業務マニュアルにあたります。

[MCP サーバー](./mcpservers.md)との役割分担は、**MCP サーバーがツール、スキルが手順**です。報告書を取得する経路がツール、取得した報告書をどう読み、何と比べ、どうまとめるかを書いたものが手順です。

## デスク専用のフォルダーに保存されます

スキルは、デスクごとに保存されます。Kari 本体・他のデスクのスキルとは別々に設定・保存されます。

[設定情報のエクスポート](./introduction.md#設定情報のエクスポートとインポート)に、スキルのフォルダーが中のファイルごと含まれます。

## SKILL.md の作成基準

スキルのフォルダーには、`SKILL.md` が1つ必要です。`---` の行で挟んだ**フロントマター**と、その下に**エージェントに伝える内容**を書きます。

```markdown
---
name: 業績診断
description: 上場企業の業績を同業他社と比較して診断するときに使う。比較指標の選び方と、レポートの構成を定める。
---

## 手順

1. 企業プロファイルから、診断対象の会社と比較対象の候補を取得する。
2. ...
```

| 項目 | 基準 |
| --- | --- |
| `name` | **必須。** スキルのフォルダー名になるため、`/` や `\` を含めたり、ピリオドで始めたり終えたりはできません。64文字以内。同じデスクの中で重複はできません |
| `description` | スキルの一覧に表示されます。省略できますが、書くことを強くおすすめします（下記） |
| 本文 | **必須。** フロントマターの下に、エージェントに伝える手順を書きます |

:::tip description には「どんなときに使うか」を書いてください

[デスク全体指示](./generalsettings.md#デスクの基本設定)が処理のたびに必ず読み込まれるのに対し、**スキルは必要になったときに読み込まれます。** その判断の手がかりになるのが `description` です。

「業績診断の手順」とだけ書くより、「**上場企業の業績を同業他社と比較して診断するときに使う**」のように、使う場面が分かるように書いてください。手順の中身を要約する欄ではなく、**いつ開くべきかを示す欄**です。

:::

## スキルを作る・取り込む・直す

設定ウィンドウの「スキル」には、デスクのスキルが一覧で並びます。

| 操作 | 内容 |
| --- | --- |
| **新規…** | 名前を付けて、フロントマター付きの `SKILL.md` を作ります |
| **インポートスキル…** | 既存のスキルフォルダーを選んで取り込みます。`SKILL.md` として読み取れないフォルダーは取り込めません |
| **編集…** | エディターを開きます。左にフォルダーのツリー、右に選んだファイルの内容が表示されます |
| **削除** | スキルとそのフォルダーを削除します。元に戻せません |
| **スイッチ** | スキルごとの有効・無効。使わないスキルはオフにしておきます |

:::note

スキルの一覧のスイッチは、ほかの設定と同じく**「保存」を押したときに書き込まれます。** 一方、スキルの作成・取り込み・削除は、押した時点でファイルに反映されます。これらは設定ではなくファイルの操作だからです。

:::

## スキルに付属するオプションファイル

スキルのフォルダーには、`SKILL.md` のほかに、手順が参照するファイルを置けます。

- **スクリプト**：Python スクリプトなど、処理の一部を決まった形で実行させたいもの。
- **テンプレート**：成果物の雛形となる `.pptx` や `.xlsx` など。
- **参照データ**：手順が引くための一覧表やデータベース。

これらは `SKILL.md` の本文から参照します。エディターのツリーでは、右クリックでファイルの追加・置き換え・削除ができます。同じ名前のファイルを取り込むときは、置き換えるかどうかを確認します（`SKILL.md` 自体は取り込みでは置き換えません。エディターで編集してください）。

## 手順の書き方

デスクのスキルは、**何を見るか、どういう順で進めるか、何を成果物に含めるか**を書く場所です。

| 書くとよいこと | 書かないほうがよいこと |
| --- | --- |
| 作業の順序と、各段階で参照するもの | 個別の案件についての判断（それは依頼ごとに変わります） |
| 成果物の構成（見出し、含める項目、出典の書き方） | AI プロバイダーやモデルの指定（設定で決めます） |
| 確認すべき点（数値の出所、記載の整合） | 成果物の送付先（設定で決めます。[成果物の送付方法](./generalsettings.md#成果物の送付方法)参照） |
| 扱えない依頼の見分け方と、その場合の返し方 | パスワードやAPIキー（資格情報は名前で参照します） |

長い詳細手順をデスク全体指示に書かず、スキルに分けるのは、**毎回読む必要のない文章を毎回読ませないため**です。デスクが複数の業務を受け持つ場合は、業務ごとにスキルを分けてください。
