# 結果の確認

依頼を出したあと、**管理者**はモニターコンソールで処理の様子を見られます。**依頼者**には、できあがった診断レポートがEメールで届きます。

## 処理の様子を見る

ブラウザで `http://localhost:28002` を開くと、モニターコンソールが表示されます。画面は[モニターコンソール](../monitorconsole.md)、または[例1：補助金診断デスクの「処理の様子を見る」](../grants/checkresult.md#処理の様子を見る)を参照してください。

一覧には、受け付けた依頼が**チケット**として並びます。チケットID、受付日時、状態、更新日時、実行時間が表示され、画面は5秒ごとに自動更新されます。

| 状態 | 意味 |
| --- | --- |
| **受付** | 受け付けて、処理の順番を待っています |
| **処理中** | エージェントが処理しています |
| **完了** | 処理が終わり、成果物を送付しました |
| **失敗** | 処理を完了できませんでした |

このデスクはジョブ並行度が **1** なので、依頼を2件続けて出すと、2件目は1件目が終わるまで「受付」で待ちます。

### チケットの中身を見る

チケットIDをクリックすると、その依頼について記録されたすべてが表示されます。

| 項目 | 内容 |
| --- | --- |
| **依頼内容** | フォームで受け付けた値。フォームのバージョンと、受け付けた経路（`web-portal`）も記録されます |
| **実行** | 開始・終了・結果・ステップ数 |
| **システムプロンプト** | その実行でエージェントに渡された指示の全文 |
| **やりとりの全文** | 依頼、エージェントの応答、ツールの結果、思考 |

「やりとりの全文」を追うと、デスクが何をしているかが分かります。このデスクの場合は、おおよそ次の順です。

1. `load_skill` で「企業業績診断スキル」を読み込む
2. `edinet-company-profiles` の `compare` で、対象企業と比較企業の指標を一度に取得する
3. 同業中央値との差が大きい指標を選ぶ
4. EDINET Util の `export_filing` で有価証券報告書を取得し、「経営者による財政状態…の分析」「事業等のリスク」などの該当箇所を読む
5. `build_report.py` でレポートを PDF に組み、`outbox/` に保存する

ツールの呼び出しは全体で15〜30回ほどが目安です。

## 診断レポートを受け取る

処理が終わると、チケットの状態が「**完了**」になり、依頼者のアドレスに送付通知が届きます。このデスクは**Eメール添付**が有効なので、PDF がメールに添付されます。ダウンロードポータルのリンクからも受け取れます。

![診断レポート](@site/docs/current/main/agentdesk/img/agentdesks_request_finance_result.png)

<div className="caption">できあがった診断レポート（PDF）</div>

ファイル名は `企業業績診断_<対象企業名>.pdf` です。レポートは次の構成になっています。

| 節 | 内容 |
| --- | --- |
| **結論** | 対象企業の強みと弱みを、同業との差で2〜4点 |
| **比較した企業** | 比較に使った企業の一覧（社名・証券コード・決算期・会計基準・連結/単体・選び方）。自動で選ばれた企業や、比較から外した企業の理由も |
| **指標の比較** | 主な指標の表（対象、同業中央値、差、順位） |
| **論点ごとの分析** | 数字の差 → 有価証券報告書に書かれている理由 → そこから考えられること |
| **今後の注目点** | 数字と記載から言えること |
| **データについて** | データの時点、決算期・会計基準・連結/単体の違い、収録していない数値 |
| **出典・ご留意事項** | EDINET の出典と加工の表示、本診断が投資助言ではないこと |

:::caution ファイルの保存期限は48時間です

ダウンロードポータルのリンクは、送付から48時間を過ぎるとファイルが削除され、リンクはその旨を表示します。Eメールに添付された控えは、この期限の対象外です。

:::

## 確認すべきこと（Human-in-the-loop のポイント）

デスクは、人が最終判断をする手前までを進める道具です。受け取ったレポートは、次の点を確かめてから使ってください。

| 確認する箇所 | 見るところ |
| --- | --- |
| **比較企業が妥当か** | 「比較した企業」の表。自動で選ばれた企業が、競合として納得できるか。同じグループの会社や、事業の違う会社が入っていないか |
| **比較の前提が揃っているか** | 同じ表の「決算期」「会計基準」「範囲（連結/単体）」。異なる会計基準が混ざっている場合、営業利益率は参考値です。決算期が違えば、各社の最新期どうしの比較になります |
| **数値の出所** | 「データについて」に書かれたデータ時点。「—（最新期の値なし）」が本文の値で補われている場合、その出所が付いているか |
| **理由づけが記載に基づくか** | 「論点ごとの分析」で、有価証券報告書の記載には出所（書類管理番号と項目名）が付き、推測は「〜と考えられる」と書き分けられているか |

:::caution

レポートの数値は、EDINET の提出書類をもとに **GotoAI が加工**したデータです。重要な判断に使う場合は、**必ず元の有価証券報告書と突き合わせて確認してください。** また、本診断は分析であって投資助言ではありません。投資の判断はご自身の責任でお願いします。

:::

## うまくいかないとき

| 状態 | 見るところ |
| --- | --- |
| チケットが「**失敗**」になる | チケットの詳細で「実行」の結果と、やりとりの全文の末尾を確認します。EDINET Util のツール呼び出しでエラーが出ている場合は、API キーの登録を確認してください（[MCP サーバーの設定](./setupmcpserver.md)） |
| 依頼を出してもチケットが増えない | デスクが停止していないか、ポート番号が 8002 のままかを確認します |
| 認証コードやレポートのメールが届かない | [Eメールの設定](./setupemails.md)の「テスト送信」で、送信アカウントが使えることを確かめます |
| 比較企業が5社に満たない | 同業候補が尽きた場合に起こります。理由はレポートの「比較した企業」に書かれます |

チケットの詳細には、デスクがその時どう考え、何を呼び出したかが全部残っています。**直し方が分かるのはたいていここ**です。情報が足りずに失敗していればリクエストフォームを、道具が足りなければ MCP サーバーやスキルを見直します。

設定を直したあとは、失敗したチケットを「**再実行**」すれば、同じ依頼で結果が変わるかを依頼者に知られないまま確認できます。
