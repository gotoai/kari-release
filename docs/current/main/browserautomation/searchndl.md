# 国会会議録を検索・分析し、議論の方向性を把握する

:::info 検証環境

本ページの手順は、以下の環境で動作を確認しています。

- **Kari**: バージョン 0.6.0 Windows
- **AI プロバイダー**: Anthropic Claude サブスクリプション
- **モデル**: Anthropic Opus 5 (1M)

:::

## ユースケースの説明
重要な議題について論点、論拠、議論の方向性を整理するには、大量の議事録・メモを読み取ったうえで情報を構造化し、分析・総括して結論を導き出す必要があります。かなりの作業量になるため、人手で行う場合、数分から数十分で終わらせることは困難です。

一方で、これは AI が得意とする作業です。必要なデータさえインプットすれば、AI は的確に処理できます。しかし多くの場合、データは従来型のシステムに格納されており、MCP や Web API など AI と連携できるインタフェースが用意されていません。このデータ連携が、AI 活用の障壁になっています。

ここで、Kari の Browser 処理自動化の機能を活用すれば、MCP や Web API がなくても、AI エージェントが文献データを検索・分析・要約できます。データ連携の障壁を越えて、AI エージェントのユースケースを簡単に実現できます。

## シナリオ
直近のフロンティア AI 減速論をきっかけに、ユーザーは、日本の政治家が AI の安全性・規制に関してどのように議論してきたか、現状はどの方向性で合意が形成されているのか、どの論点で意見が分かれているのかを知りたいと考えています。

本事例では、国立国会図書館の「国会会議録検索システム」を対象に、直近3年分の会議録を横断検索し、論点別の構造化一覧と対立軸を出力させます。

## 作業の準備

- 左のナビパネルの「Web ブラウザ」を開き、対象のページを表示します。  
URL: https://kokkai.ndl.go.jp/

![国会会議録検索システム](@site/docs/current/main/browserautomation/img/search_ndl.png)

- このシステムには、第1回国会（昭和22年5月）以降の本会議・委員会の会議録が収録されています。トップページには「検索して探す」（キーワード検索）、「会議録を選択して探す」（開催日・院名・会議名から選択）、「法律案・条約承認案件の審議経過から探す」の3つの入口があります。

- 実際にキーワードを1つ入れて検索し、**結果の見え方を確認しておきます**。会議録単位で一覧が出ること、各件に「テキスト表示」「該当箇所を展開」といったリンクがあることを把握しておくと、後で AI の報告を検証しやすくなります。

:::tip

このシステムは検索用の API も公開しています。AI は、件数の把握や会議名の絞り込みには検索画面を、発言本文の正確な取得には API を、といった使い分けを自分で選ぶことがあります。どちらもブラウザ経由の閲覧であり、指示の範囲内です。

:::

## AI に作業を指示

- 調査の背景、検索方針、出力形式、そして引用の扱いをまとめて、以下のように AI に作業を指示します。

```text title="AI への指示"
今開いている「国会会議録検索システム」を起点に、AIの安全性・規制に関する国会での議論を調査し、結果を報告してください。

0. アクセス上の遵守事項
(1) ページ遷移の間隔は1秒以上空け、同時並行のリクエストは行わないでください。
(2) CAPTCHA、アクセス制限、エラー画面が表示された場合は、回避を試みず作業を中断し、その旨を報告してください。

1. 背景：現在、フロンティアAI開発の減速論が議論されており、日本の立法・行政がAIの安全性とリスクをどう捉えてきたかを、国会での実際の発言から把握します。

2. 検索方針
(1) Browserツールを使用し、Web Fetchツールを使わないでください。
(2) 直近3年を主対象とします。
(3) 検索条件、キーワードを適宜作成してください。
(4) 院・会議名は絞らず横断検索し、ヒットが多い場合のみ委員会を限定して絞り込んでください。

3. 出力
(1)チャットの返信本文に、箇条書き＋表で出力
(2) 主な報告項目：
　(i) 調査した会議録のリスト
　(ii) 論点別の構造化一覧。論点（例えば、安全性評価／規制手法／国際協調／産業競争力とのバランス 等）× 主な主張 × 発言者の立場。
　(iii) 見えている傾向、対立軸、課題、示唆
　(iV) 実施した検索条件とヒット件数の一覧

4. 引用の扱い
(1) 発言の引用は論点ごとに複数の発言者を横断する形とし、特定の1名の発言を集めて編集する構成にはしないでください。
(2) 引用内容は完全に事実に基づき、推測・補完しないでください。
```

![AI に国会会議録の調査を指示する](@site/docs/current/main/browserautomation/img/search_ndl_prompt.png)

この指示の組み立て方には、次のポイントがあります。

| 指示のブロック | ねらい |
| --- | --- |
| 0. アクセス上の遵守事項 | 公共機関のシステムに負荷をかけないよう、間隔と直列実行を明示します。 |
| 1. 背景 | **なぜ調べるのかを与えます。** 検索キーワードの選定と論点の切り分けを AI に委ねるため、判断の基準となる文脈が必要です。 |
| 2. 検索方針 | 期間と横断範囲を指定する一方、**キーワードは AI に作らせます**。会議録の語彙は一般的な用語と異なることがあり、検索語を固定するとかえって取りこぼします。(4) で「まず横断、多すぎたら絞る」という手順も指定しています。 |
| 3. 出力 | (i) の会議録リストと (iV) の検索条件一覧が**追跡と再現のための情報**です。結論だけでなく、どこを見て、どう探したかを必ず出させます。 |
| 4. 引用の扱い | **この事例で最も重要な指定です。**「特定の1名の発言を集めて編集する構成にしない」と明示することで、特定の政治家の主張として切り取られる形の出力を防ぎます。あわせて逐語引用のみとし、推測・補完を禁じます。 |

:::caution

政治的な発言を扱う調査では、**出力の構成そのものが偏りを生みます。** 論点を軸にするか、人物を軸にするかで、同じ発言集合からまったく異なる印象の資料ができあがります。指示の段階で構成を指定してください。

:::

## AI の作業結果を確認

- AI は検索画面で条件を変えながら検索を実行し、会議録を読み込んだうえでレポートを出力します。まず「調査方法と前提」で、対象期間・検索範囲・使用ツール・引用方針を確認します。

![調査方法と前提](@site/docs/current/main/browserautomation/img/search_ndl_result.png)

この例では、次のことが報告されています。

- 対象期間は令和5年9月（2023-09）以降〜2026-09-18 の直近3年。院・会議名は横断（衆議院／参議院／両院協議会・合同審査会等すべて）で、ヒットが多い検索のみ会議名で絞り込んだ。
- 使用ツールは Browser ツールのみ（Web Fetch は未使用）。**検索画面と、同システムが公開する検索用 API（`/api/speech`、`/api/meeting_list`）をブラウザで併用**し、前者で件数把握と会議名の絞り込みを、後者で発言本文の正確な取得を行った。
- 引用方針は会議録本文からの逐語引用のみ。推測・補完はしていない。全角の「ＡＩ」等は原文表記に従っている。

- 続いて、調査した会議録のリストが出力されます。「国会回次・院・会議」「号・日付」「主な発言者」の3列で、**どの会議録を読んだか**が1件ずつ特定できます。

![調査した会議録のリスト](@site/docs/current/main/browserautomation/img/search_ndl_result2.png)

- 論点別の構造化一覧が、論点ごとに「主な主張」「発言者（立場）」「逐語引用」の3列の表で出力されます。発言者には所属と立場（政府・野党・参考人など）が併記されます。

![論点別の構造化一覧](@site/docs/current/main/browserautomation/img/search_ndl_result3.png)

- 傾向として、議論の重心が時系列でどう移動したかがまとめられます。

![見えている傾向](@site/docs/current/main/browserautomation/img/search_ndl_result4.png)

この例では、制度の中心軸が AI 法（令和7年5月成立、第217回国会）であること、安全性の語り方が「規制するか否か」から「評価できるか」「制御可能な状態に置けるか」へ移行したこと、AI 専門の審査体制が整備途上で審議が多数の委員会に分散していることが指摘されています。

- 最後に、対立軸が「軸」「一方の側」「他方の側」の3列の表で整理されます。

![対立軸](@site/docs/current/main/browserautomation/img/search_ndl_result5.png)

規制の法形式、理念の書き込み、規制の実効性の担保方法、国際戦略の基調、安全性と自律性の優先順位という5つの軸が抽出されています。あわせて、**「AI 法案に対する反対の討論」は本期間の会議録に該当がなかった（該当0件）**ことが注記され、対立が法案の可否ではなく制度の厚みをめぐるものとして現れている、と説明されています。

## Human-in-the-loop のポイント

AI に任せきりにせず、次の点は人が確認してください。

- **逐語引用を原本と照合する**  
本事例の出力には、実在の政治家・官僚・参考人の氏名、所属、発言が含まれます。**誤りがあれば、実在の個人に誤った発言を帰属させることになります。** 会議録リストの「国会回次・院・会議」「号・日付」から元の会議録を開き、引用が原文どおりか、発言者の取り違えがないかを確認してください。資料として外部に出す場合は、全件の照合が必要です。

- **「該当0件」という報告を鵜呑みにしない**  
「AI 法案に対する反対の討論は該当0件」は強い主張です。これは AI が使った検索語の範囲で見つからなかったという意味であり、存在しないことの証明ではありません。重要な結論が「なかった」である場合は、検索条件一覧を見て、別の語彙でも試してください。

- **発言者の「立場」ラベルを確認する**  
参考人の発言は、その人が招致された会議での意見であり、所属組織や党派の公式見解とは限りません。政府参考人の答弁と、議員の質疑と、参考人の意見は性質が異なります。AI が付けた立場ラベルが、この区別を保っているかを見てください。

- **検索条件とヒット件数から網羅性を判断する**  
出力された検索条件一覧は、調査の範囲を示す情報です。ヒット件数が極端に少ない条件や、想定した委員会が対象に入っていない場合は、追加の指示で補ってください。

- **人物軸への組み替えを安易に行わない**  
「特定の1名の発言を集めない」という指示は、出力を受け取った後にも適用されます。論点軸で整理された結果を人物軸に組み替えると、指示で避けた偏りが復活します。

- **会議録の性質を踏まえる**  
会議録は発言の記録であり、発言内容の正しさを保証するものではありません。AI が整理した「傾向」も、会議録という限られた資料から見える範囲の傾向です。

- **アクセス手段を確認する**  
本事例では、AI が検索画面と公開 API を併用しました。合理的な選択ですが、意図した経路と異なる場合があります。「調査方法と前提」の記載を読み、想定どおりかを確かめてください。

:::caution

使用する LLM により、読み取りの精度や論点の切り分けが変わることがあります。引用と固有名詞は、必ず元の会議録と突き合わせて確認してください。

:::
