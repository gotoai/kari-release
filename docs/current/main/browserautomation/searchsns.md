# SNS にサインインし、パブリック・オピニオンを分析する

:::info 検証環境

本ページの手順は、以下の環境で動作を確認しています。

- **Kari**: バージョン 0.6.0 Windows
- **AI プロバイダー**: Anthropic Claude サブスクリプション
- **モデル**: Opus 5 (1M)

:::

## ユースケースの説明
ホットトピックについて大勢の人の意見を知りたい、議論の状況や方向性を把握したい、と考えるときに、ソーシャルメディアの投稿を一件ずつ見ていくと、多大な時間がかかります。

Kari の Browser 処理自動化の機能を活用すれば、自分の SNS アカウントから見える意見を整理・要約する作業を、AI エージェントに依頼できます。

## シナリオ
ユーザーは、直近のフロンティア AI 減速論の話題が気になっており、自分がよく使っている SNS である mastodon.social で、どのような議論が交わされているか、賛否どちらの意見が優勢かを知りたいと考えています。ただし、そこに長い時間をかけたくないと考えています。AI エージェントを活用すると、下記のメリットがあります。

- Web スクレイピングやボットによる自動巡回ではなく、**ユーザーの代行としてサインイン済みのブラウザを操作します**。明示的に設定した動作条件（アクセス間隔、閲覧件数の上限、閲覧のみで書き込みは行わない）の範囲で動作するため、対象サービスの利用条件に沿った形で作業を進められます。  
（* 本事例では mastodon.social を用いて説明するにあたり、当該 SNS の規約に違反しないことを確認しています。対象 SNS が異なる場合は、必ずご自身で規約を確認したうえで進めてください）
- 多言語の投稿をそのまま読み取り、同じ基準で分類できます。
- 引用情報の一覧化と論点の要約をまとめて実行できるため、整理にかかる時間を大幅に短縮できます。

## 作業の準備

:::caution 最初に確認すること

対象 SNS の利用規約・API ポリシー・`robots.txt` を確認し、**ブラウザによる閲覧の自動化が許容される範囲**を把握してください。アクセス間隔や取得件数の上限を指示に書き込むのは、依頼する側の責任です。許容範囲が読み取れない場合は、作業を行わないでください。

:::

- 左のナビパネルの「Web ブラウザ」を開き、対象の SNS に**自分のアカウントでサインイン**します。本事例では mastodon.social を使用し、サインインしている状態で実施します。  
URL: https://mastodon.social/

![mastodon.social にサインインした状態](@site/docs/current/main/browserautomation/img/search_sns_timeline_trend.png)

- 収集の起点となるページを開きます。本事例では「トレンド」ページを起点にします。  
URL: https://mastodon.social/explore

![mastodon.social のトレンドページ](@site/docs/current/main/browserautomation/img/search_sns_timeline_mastodon.png)

- 起点のページをひととおり眺め、**どのような投稿が並んでいるか**を確認しておきます。この時点では話題が雑多で、目的のトピックが見当たらないこともあります。それ自体が後で意味を持つ情報になります。

:::tip

AI は、ユーザーがサインインしたブラウザのセッションをそのまま使います。ログインが必要な社内 SNS やクローズドなコミュニティでも、同じ手順で作業を依頼できます。

:::

## AI に作業を指示

- 収集の範囲、分類の定義、アクセス上の遵守事項をまとめて、以下のように AI に作業を指示します。

> 現在開いているmastodon.socialのトレンドページを起点に、フロンティアAI開発の減速論に関する公開投稿を収集し、論点を整理して報告してください。
>
> 0. アクセス上の遵守事項  
> (1) リクエストは1件ずつ逐次実行し、1件ごとに1.5秒以上空けてください。  
> (2) 閲覧するタグは最大10個、読み取る投稿は合計最大100件までとします。  
> (3) 画像・動画をダウンロードしないでください。  
> (4) CAPTCHA、アクセス制限、エラー画面が表示された場合は、回避を試みず作業を中断し、その旨を報告してください。  
> (5) あらゆる書き込み操作は一切禁止です。閲覧のみを行ってください。
>
> 1. 使用ツール：Browserツールを利用し、Web Fetchツールを使わないでください。
>
> 2. 調査対象の範囲  
> (1) 原則として直近72時間以内に投稿された日本語、英語のメッセージを対象とします。  
> (2) フロンティアAI開発の減速・の是非に言及している投稿のみを対象とします。AIへの一般的な言及、製品紹介、画像生成作品の投稿などは対象外です。  
> (3) 明らかなbot投稿、ニュース見出しの自動転載、同一内容の重複ブーストは除外してください。  
> (4) 新しい論点が出てこなくなった（飽和した）と判断した時点で、収集を中断して構いません。その判断根拠も報告してください。
>
> 3. 立場の分類（以下の定義に従ってください）  
> 　・賛成: 開発を減速するべきという立場  
> 　・反対: 減速すべきでない、開発は継続・加速すべきという立場  
> 　・中立/両論: 条件付き、論点整理のみ、どちらとも取れるもの  
> 　・判定不能: 皮肉・アイロニー・文脈不足で立場が確定できないもの。「判定不能」に無理に立場を割り当てないでください。
>
> 4. 出力（チャットの返信本文に、箇条書き＋表で）  
> (1) 収集条件の記録：閲覧したタグ名、取得時刻（UTC）、対象期間、読み取った投稿数  
> (2) 立場ごとの件数。必ず次の注記を併記してください：「これは収集したサンプル内の内訳であり、母集団を代表しない。」  
> (3) 論点別の整理。論点（例えば、安全性の実証可能性／規制手法／国際競争／環境負荷／雇用 等）× 主張の要旨 × 立場。  
> (4) 各論点の典型例として、投稿のURLを1〜2件ずつ提示してください。  
> (5) 見えている傾向、対立軸、示唆。72時間以内に特定のニュースが議論を牽引している場合は、その出来事を明記してください。

![AI に SNS の投稿収集を指示する](@site/docs/current/main/browserautomation/img/search_sns_search_prompt.png)

この指示の組み立て方には、次のポイントがあります。

| 指示のブロック | ねらい |
| --- | --- |
| 0. アクセス上の遵守事項 | アクセス間隔・閲覧タグ数・投稿数の上限を数値で与え、作業量を制御します。**(5) の「あらゆる書き込み操作は一切禁止」は SNS 特有の指定**で、返信・ブースト・お気に入り・フォローを誤って実行させないための歯止めです。 |
| 1. 使用ツール | ブラウザのサインイン状態を使うため、ツールを Browser に限定します。Web Fetch では、ログインが必要なページや当該インスタンスの表示を取得できません。 |
| 2. 調査対象の範囲 | 期間・言語・トピックで対象を絞り、bot 投稿や自動転載を除外します。**(4) で「飽和したら中断してよい」と明示**し、あわせて判断根拠を報告させることで、網羅していないことを AI 自身に申告させます。 |
| 3. 立場の分類 | 分類の定義を与え、さらに**「判定不能」という受け皿を用意**します。皮肉や文脈不足の投稿を無理に賛否へ割り当てさせないための指定です。 |
| 4. 出力 | **(2) で「母集団を代表しない」注記を必須化**し、件数の統計的な誤読を防ぎます。(4) で典型例の URL を出させることで、人が元投稿に当たって検証できます。 |

:::caution

SNS では、閲覧のつもりの操作が誤って書き込みになることがあります（ボタンの押し間違い、キーボードショートカットなど）。「閲覧のみ」を指示に明記したうえで、作業後にアカウントの投稿履歴・通知を確認してください。

:::

## AI の作業結果を確認

- AI は起点のトレンドページからタグをたどって投稿を読み取り、レポートをセッションウィンドウに出力します。まず「遵守事項の履行状況」で、指示した上限が守られているかを確認します。

![遵守事項の履行状況と収集条件の記録](@site/docs/current/main/browserautomation/img/search_sns_search_result.png)

この例では、次のことが報告されています。

- リクエストはすべて逐次1件ずつ実行し、各リクエスト間に1.6秒以上のスリープを挿入した。
- 閲覧タグ数は**4個**（上限10個以内）、読み取り投稿数は**97件**（上限100件以内）。
- 画像・動画のダウンロードは行っていない（テキストの読み取りのみ）。CAPTCHA・アクセス制限・エラー画面には遭遇していない。
- 書き込み操作は一切行っていない（返信・ブースト・お気に入り・フォロー等のボタンは未操作）。
- 収集条件の記録として、起点 `https://mastodon.social/explore`、取得時刻 2026-09-18 04:05〜04:20 UTC、対象期間は直近72時間が明示されている。

- 続いて、立場ごとの件数が表で出力されます。指示した注記が併記されていることを確認します。

![立場ごとの件数](@site/docs/current/main/browserautomation/img/search_sns_search_result2.png)

読み取った97件のうち、**対象条件に該当したのは15件**（賛成2／反対3／中立・両論8／判定不能2）でした。「これは収集したサンプル内の内訳であり、母集団を代表しない。」という注記と、言語別の内訳（英語15件／**日本語0件**）が併記されています。

- 論点別の整理が、「論点」「主張の要旨」「立場」の3列の表で出力されます。

![論点別の整理](@site/docs/current/main/browserautomation/img/search_sns_search_result3.png)

- 最後に、傾向・対立軸・示唆がまとめられます。議論を牽引している72時間以内の出来事が、日付とともに列挙されます。

![傾向・対立軸・示唆](@site/docs/current/main/browserautomation/img/search_sns_search_result4.png)

この例では、「実証責任の所在」「主体の正統性」「国際協調の実効性」という3つの対立軸が抽出されています。あわせて、**「減速論は mastodon.social ではトレンド化していない」**という所見が、根拠となる数字（トレンドタグ上位10件に AI 関連は0件、`#PauseAI` はタグ全体で2投稿・本日0件、`#AI規制` は最新投稿が3週間前）とともに報告されています。

:::tip

「議論が盛り上がっていない」という結果も、それ自体が調査の成果です。件数が少ないときは、AI にそう報告させたうえで、**根拠となった数字を必ず添えさせて**ください。

:::

## Human-in-the-loop のポイント

AI に任せきりにせず、次の点は人が確認してください。

- **件数を「世論」と読み替えない**  
本例の内訳は、AI が読み取った97件のうち条件に該当した15件のものです。母集団の縮図ではありません。賛成2件・反対3件という数字から優勢・劣勢を論じることはできません。AI に出させた注記は、この誤読を防ぐためのものです。

- **言語と観測範囲の偏りを確認する**  
指示では日本語と英語を対象としましたが、該当は**英語15件・日本語0件**でした。これは「日本語話者が関心を持っていない」ことではなく、**このインスタンスで可視化される範囲にたまたま日本語の投稿がなかった**ことを示します。SNS の分析結果は、どのアカウントで、どのインスタンスから見たかに強く依存します。

- **「判定不能」の中身を読む**  
皮肉やアイロニーは、AI が最も誤りやすい領域です。本例でも2件が判定不能とされています。判定不能とされた投稿は元の文面に当たり、無理に賛否へ振り分けられていないかを確認してください。

- **典型例の URL を実際に開く**  
論点表の「主張の要旨」は AI による要約です。少なくとも各論点につき1件は元投稿を開き、要約が投稿者の主旨からずれていないかを確認してください。

- **書き込みが発生していないことを確認する**  
作業後にアカウントの投稿履歴・ブースト履歴・通知を確認し、意図しない書き込みが発生していないことを確かめてください。

- **収集の打ち切り根拠を読む**  
「飽和した」という判断は AI のものです。閲覧タグが4個で止まっている場合、それが本当に飽和だったのか、たどるべきタグを見落としたのかは人が判断します。

- **投稿の引用は慎重に扱う**  
公開投稿であっても、投稿者のアカウント名や本文をそのまま社外資料へ転載することは、対象サービスの規約や投稿者の意図に反する場合があります。二次利用の可否は、利用者ご自身の責任でご判断ください。

:::caution

使用する LLM により、立場の分類や要約の精度が変わることがあります。同じ投稿でも分類が分かれることがあるため、件数は目安として扱い、重要な判断には元の投稿を直接確認してください。

:::
