# 政府統計のデータを検索・抽出し、分析から示唆出しまで実施する

:::info 検証環境

本ページの手順は、以下の環境で動作を確認しています。

- **Kari**: バージョン 0.6.0 Windows
- **AI プロバイダー**: Anthropic Claude サブスクリプション
- **モデル**: Anthropic Opus 5 (1M)

:::

## ユースケースの説明
政府統計の総合窓口「e-Stat」は、サイトの説明にあるとおり「日本の統計が閲覧できる政府統計ポータルサイト」です。Web ブラウザを通じて、豊富なデータを検索・ダウンロードできます。

多くの企業も、同様の社内データポータルを構築しています。しかし、データが大量にあっても、そのままでは示唆のある分析結果にはなりません。従来のデータ分析では、分析者がビジネス上の意図を明確にしたうえで、データセットの選定、仕様・品質の確認、探索・仮説検証といった一連の作業を行い、そこから有用な示唆を抽出します。当然ながら、多くの作業時間を要します。

Kari の Browser 処理自動化の機能を活用すれば、AI エージェントがブラウザを通してデータの選定・仕様や品質の確認・探索・仮説検証を実施し、データ分析から示唆出しまでを一貫して進められます。

## シナリオ
ユーザーは、日本の飲食業における非正規雇用の賃金状況を把握したいと考えています。どの統計表を使えばよいかは分かっていません。データセットの選定から数値の抽出、傾向の読み取りまでを AI エージェントに任せます。

本事例では、e-Stat を起点に、直近5年分のデータを探し出して数値を整理させ、傾向・課題・示唆までを出力させます。

## 作業の準備

- 左のナビパネルの「Web ブラウザ」を開き、対象のページを表示します。公開データの閲覧にサインインは不要です。  
URL: https://www.e-stat.go.jp/

![e-Stat のトップページ](@site/docs/current/main/browserautomation/img/search_estat.png)

- 「統計データを探す」には「すべて」「分野」「組織」の3つの入口とキーワード検索があります。どの統計を使うかが決まっていない場合も、AI にキーワードから探させられます。

:::caution API が使える場合はそちらを検討してください

e-Stat は「統計データの自動取得（API）」を提供しています。**大量のデータを定型的に取得する用途では、API のほうが確実で、サイトへの負荷も小さくなります。** 本ページの手順が向くのは、どの統計表を使うかが決まっておらず、**探しながら絞り込む**段階の作業です。

:::

## AI に作業を指示

- 調べたいテーマと、出典の記載・計算値の区別といった統計データ特有の制約をまとめて、以下のように AI に作業を指示します。

> 今開いているe-Statページから、日本の飲食業における非正規雇用の賃金状況に関するデータセットを探し、必要な数値を抽出・整理して結果を報告してください。
>
> 0. アクセス上の遵守事項  
> (1) 短時間に連続してリクエストを送らないでください。ページ遷移の間隔は1秒以上空け、同時並行のリクエストは行わないでください。  
> (2) CAPTCHA、アクセス制限、エラー画面が表示された場合は、回避を試みず作業を中断し、その旨を報告してください。  
> (3) 出力には出典（政府統計の総合窓口(e-Stat)＋調査名・統計表名）を必ず記載してください）。  
> (4) 自分で計算した数値は、政府の公表値と区別できる形で示してください
>
> 1. Browserツールを使用し、Web Fetchツールを使わないでください。
>
> 2. 年次または年度別のデータがあれば、直近5年分のデータを使ってください。
>
> 3. 調査結果を箇条書き＋表で、以下の項目を含めてチャットメッセージで出力してください。  
> (1) 活用したデータセット  
> (2) 非正規雇用の労働者数、労働時間、賃金水準  
> (3) 見えている傾向、課題、示唆など

![AI に e-Stat のデータ分析を指示する](@site/docs/current/main/browserautomation/img/search_estat_prompt.png)

この指示の組み立て方には、次のポイントがあります。

| 指示のブロック | ねらい |
| --- | --- |
| 0. アクセス上の遵守事項 (1)(2) | サイトに負荷をかけないよう、間隔と直列実行を明示します。 |
| 0. (3) 出典の記載 | **調査名と統計表名まで**書かせます。「e-Stat より」だけでは、どの表のどの系列かが特定できず、検証できません。 |
| 0. (4) 計算値の区別 | **この事例で最も重要な指定です。** 政府統計では、公表値と、そこから割り算などで導いた値の区別が決定的に重要です。この一文により、AI は計算値に【自算】と付けて出力します。 |
| 1. 使用ツール | ブラウザ操作に限定します。 |
| 2. 期間 | 「年次または年度別のデータが**あれば**」という条件付きの指定です。データの粒度を AI に確認させたうえで期間を決めさせます。 |
| 3. 出力 | (1) の「活用したデータセット」が追跡のための情報です。結論だけでなく、どの表から取ったかを必ず出させます。 |

:::caution

統計データの分析では、**数値の出どころが曖昧になることが最大のリスクです。** 公表値・計算値・推測の3つは、必ず区別させてください。指示に書かなければ、これらは混ざって出力されます。

:::

## AI の作業結果を確認

- AI は e-Stat の検索条件を操作しながら候補となる統計表を絞り込み、該当するファイルをダウンロードして読み取ります。処理中はツールの実行状況がセッションウィンドウに表示されます。

![AI が統計表を絞り込んでいる様子](@site/docs/current/main/browserautomation/img/search_estat_aifiltering.png)

- 実行が終わると、まず「活用したデータセット」が出力されます。出典と統計表名、提供分類、使用年が表で示されます。

![活用したデータセット](@site/docs/current/main/browserautomation/img/search_estat_result.png)

**この節に、この事例で最も重要な報告が含まれています。**

- 出典は「政府統計の総合窓口（e-Stat）／厚生労働省『賃金構造基本統計調査』」。使用した統計表が3つ、それぞれ統計表名まで特定されています。
- **⚠ 重要な制約**：本調査で「雇用形態 × 産業」をクロス集計できるのは**産業大分類まで**であり、中分類「76 飲食店」単独の非正規データは提供されていない。したがって以下の数値は**宿泊業を含む M 大分類**の値である。
- データベース形式は2020〜2023年までしか収録がないため、直近5年を揃えるためにファイル形式（Excel）を使用した。
- 3つ目の統計表は**（検証用）**として、産業計〜J金融業，保険業のデータも取得している。

つまり AI は、**ユーザーが求めた粒度のデータが存在しないことを発見し、代替の粒度を選び、その差を明示している**ことになります。これは分析作業における仕様・品質確認そのものです。

- 続いて、労働者数・労働時間・賃金水準が表で出力されます。

![非正規雇用の労働者数](@site/docs/current/main/browserautomation/img/search_estat_result2.png)

列見出しに注目してください。「一般・正社員」「一般・非正社員」「短時間・非正社員」は公表値ですが、「非正規合計【自算】」「全体【自算】」「非正規比率【自算】」には**【自算】**が付いています。表の下には「公表値は『十人』単位のため10倍して人数化。『非正規合計』『全体』『非正規比率』は筆者による計算値」と注記されています。指示の 0.(4) が守られています。

![賃金水準](@site/docs/current/main/browserautomation/img/search_estat_result3.png)

賃金水準も同様に、公表値の表（所定内給与・年間賞与）と、【自算】の表（時間給換算・年収換算）が分けて示されています。

- 最後に、傾向・課題・示唆がまとめられます。

![見えている傾向・課題・示唆](@site/docs/current/main/browserautomation/img/search_estat_result4.png)

非正規比率が80.6%（2021年）から83.1%（2025年）へ上昇していること、時給は上昇しているが労働時間が縮小しているため月収換算は時給ほど増えていないこと、格差は賃金より賞与に集中していることなどが挙げられています。2021年の異常値については、**検証用に取得した産業計のデータでも同方向の動きを確認したうえで「データの読み取りミスではない」と判断**し、その原因の解釈については「この解釈は筆者の推測」と明記されています。

## Human-in-the-loop のポイント

AI に任せきりにせず、次の点は人が確認してください。

- **【自算】と公表値の区別を確認する**  
資料として使う際は、**どの数値が政府の公表値で、どの数値が AI の計算値かを必ず区別してください。** 計算値を公表値として引用すると、出典の誤りになります。【自算】の付いた数値は、計算式（分子・分母に何を使ったか）まで確認してください。

- **データの粒度の制約を読む**  
本例の数値は「飲食業」ではなく、**宿泊業を含む産業大分類 M** の値です。この制約を見落として「飲食業の非正規比率は83.1%」と引用すると、誤りになります。AI が制約を報告していても、読み飛ばせば意味がありません。

- **単位の扱いを確認する**  
本例では公表値が「十人」単位のため、AI が10倍して人数に換算しています。統計表には、単位、秘匿値、「-」や「X」の記号など、そのままでは計算に使えない表記が含まれます。元の統計表を開いて、換算が妥当かを確認してください。

- **事実と解釈を切り分ける**  
「2021年はコロナ影響で異常値」という記述のうち、**数値の動きは事実、原因の説明は推測**です。本例では AI が「この解釈は筆者の推測」と明記していますが、この区別が付いていない出力もあり得ます。

- **出典を統計表名まで確認する**  
「活用したデータセット」の統計表名で e-Stat を検索し、同じ表にたどり着けるかを確認してください。統計表が特定できなければ、数値は検証できません。

- **収録期間の違いに注意する**  
本例では、データベース形式とファイル形式で収録期間が異なりました。同じ調査でも提供形式によって使えるデータが変わります。「直近5年」のような相対指定では、どの形式から取ったかを確認してください。

- **API の利用を検討する**  
継続的に同じデータを取得するなら、e-Stat の API のほうが確実です。ブラウザ自動化は、探索段階の作業に向いた手段です。

:::caution

使用する LLM により、統計表の選定や数値の読み取り精度が変わることがあります。数値は、必ず元の統計表と突き合わせて確認してください。

:::
