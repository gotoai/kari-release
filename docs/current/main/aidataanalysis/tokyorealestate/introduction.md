# 概要

## ユースケースの説明

ビジネスデータ分析の目的は、データから有用な情報を抽出し、意思決定に資する示唆を得ることです。しかし AI を使わない従来の進め方では、生データのクレンジング・整形・集計に大きな工数がかかります。しかも、仮説を組み替えるたびに、同じ処理をやり直すことになります。その結果、データを入手してから示唆を得るまでに長い時間を要することが少なくありません。

Kari の AI エージェントを活用すれば、生データの構造の解析、仮説に基づくデータ処理、そして結果の可視化までを一貫して任せられます。仮説を変更しても処理のやり直しが短時間で済むため、限られた時間の中で試行の回数を増やせます。本事例を通して、データ分析の生産性がどこまで上がるかを確かめてください。

## シナリオ

マイホームの購入、または不動産投資の観点から、東京都23区の不動産価格を分析します。検証する仮説は、たとえば次のようなものです。

- 不動産の価格は、どのような要素と相関するか
- 不動産の価格上昇率は、地域によってどのように違うか
- その上昇率は、人口の増減などの環境要因と相関するか

従来であれば、こうした検証はデータ分析の専門家に依頼し、多くの作業時間を要するものでした。AI エージェントを活用すれば、同じ検証を自前で、しかも短時間で進められます。

## 扱うデータの性質

分析を始める前に、**何を見ているのか**を押さえてください。国土交通省「不動産情報ライブラリ」の価格データには、性質の異なる2つの出所が含まれており、どちらも「市場の全体」ではありません。

| | 不動産取引価格情報 | 成約価格情報 |
| --- | --- | --- |
| 出所 | 国土交通省が不動産取引当事者に行う**アンケート調査**の回答 | 宅建業者が**レインズ**に登録した成約情報。「レインズ・マーケット・インフォメーション」（RMI）を通じて提供 |
| 集め方 | 公示されている不動産登記情報をもとに、購入者へ調査票を送付 | 媒介した取引が成約した際に、宅建業者が登録 |
| 対象となる種類 | 宅地（土地）、宅地（土地と建物）、中古マンション等、農地、林地 | 【土地と建物】（＝戸建て）と【中古マンション等】のみ |

本事例で取得した207,636件の内訳は、不動産取引価格情報 103,769件、成約価格情報 103,867件で、ほぼ半々です。**1つの表に見えても、中身は由来の違う2系統のデータです。**

:::caution 分析の前に押さえておきたい4点

**1. 契約の記録ではなく、アンケートの回答です。全数ではありません。**

不動産取引価格情報は、登記情報をもとに購入者へ送ったアンケートの回答を集めたものです。回答が得られなかった取引は含まれません。成約価格情報も、宅建業者がレインズに登録した取引、すなわち**仲介を伴う取引**が対象です。いずれも、その期間に起きた全ての取引を網羅したものではありません。

**2. 取引価格は有効数字2桁に丸められています。**

個別の物件が容易に特定できないよう加工されているためです。本事例で取得した全207,636件を調べたところ、`13,000,000` `32,000,000` `85,000,000` `640,000,000` のように、**100%が有効数字2桁以内**でした。したがって、数パーセントの価格差を論じることや、平均値の下位の桁に意味を見出すことはできません。所在地も町・大字レベルまでで、番地はありません。

**3. 同じ取引が両方に含まれている可能性があります。**

仲介業者を介した戸建ての売買は、レインズへの登録（成約価格情報）と、購入者へのアンケート（不動産取引価格情報）の双方に現れうる関係にあります。全件を単純に合算して平均を出すと、**同じ取引を二重に数える**おそれがあります。「価格情報区分」で分けて集計するか、どちらか一方に絞って分析してください。

**4. 直近の期のデータは、後から変わります。**

サイトの「留意事項」に、取引価格情報のデータ数はアンケートの収集状況により今後も変わる可能性があり、**特に最新の期は翌期以降大きく変わることがある**と明記されています。直近の四半期を含む分析では、取得日を記録し、結論をその時点のものとして扱ってください。

:::

:::tip 列の埋まり方も出所によって違います

同じ表に並んでいても、どの列が埋まっているかは出所ごとに異なります。本事例のデータでは、「建ぺい率（％）」が空である割合は、不動産取引価格情報で **0.5%**、成約価格情報で **84.5%** でした。片方にしか入っていない列を使って全体を語ってしまわないよう、集計の前に「価格情報区分」ごとの欠損を確認してください。

数値に見えて数値でない列もあります。「建築年」は `1990年`、「取引時期」は `2021年第2四半期` という文字列で、「面積（㎡）」には `2,000㎡以上`、「最寄駅：距離（分）」には `30分～60分` `1H～1H30` のような範囲・打ち切りの表記が混じります。これらをどう型付けするかは、[AI による生CSVデータの解析自動化](./parserawdata.md)で扱います。

:::

出典・参考：

- 不動産情報ライブラリ（国土交通省） https://www.reinfolib.mlit.go.jp/realEstatePrices/
- 不動産取引価格情報提供制度（国土交通省） https://www.mlit.go.jp/totikensangyo/totikensangyo_tk5_000069.html

## 本事例の進め方

本事例は、次の手順で進めます。

1. [国交省不動産情報ライブラリから、東京都23区の不動産価格データを取得する](./retrievedata.md)
2. [Kari の「AI解析」機能を活用して生のCSVデータの解析を自動化させる](./parserawdata.md)
3. [AI により変数の構成比率を可視化させてデータの構造を確認する](./analyzedataratio.md)
4. [中古マンション等の単位面積価格と他の変数との相関を分析する](./pricecorrelation.md)
5. [中古マンション等の単位面積価格の上昇率をセグメント別で分析する](./pricegrowthsegment.md)
6. [中古マンション等の単位面積価格の上昇率と人口の増減率の相関を分析する](./populationcorrelation.md)

手順1から3が**分析の準備**、手順4から6が**分析そのもの**です。準備では、生の CSV をテーブルにし、どの列に何がどれだけ入っているかを確認します。**使えない列や欠損の多い列を先に把握しておく**ことが、以降の分析の精度を決めます。

分析の3ページは、問いが段階的に変わります。

| 手順 | 問い |
| --- | --- |
| 4 | 価格は**何と一緒に動く**のか |
| 5 | **どういう条件の物件**が、いちばん値上がりしてきたか |
| 6 | 人が集まっている区ほど、価格が上がっているのか |

手順6では、**不動産データの外に出て**東京都の人口統計を取得し、区単位で突き合わせます。

:::caution

本事例で扱うのは、実際の不動産取引価格のデータです。分析結果を購入や投資の判断に用いる場合は、**AI の出力した数値を必ず元データと突き合わせて確認してください。** 各ページの「Human-in-the-loop のポイント」に、確認すべき箇所を記載しています。

:::
