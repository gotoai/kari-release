# 観光庁・JNTO・法務省のWebページから、分析のための必要データを取得する

:::info 検証環境

本事例の手順は、以下の環境で動作を確認しています。

- **Kari**: バージョン 0.7.3 Windows
- **AI プロバイダー**: Anthropic Claude サブスクリプション
- **モデル**: Claude Opus 5.5 High
:::

## 作業の準備

このページでは、**3つの公的機関から別々のデータ**を取得します。

| | 観光庁 | JNTO（日本政府観光局） | 法務省（出入国在留管理庁） |
| --- | --- | --- | --- |
| データ | インバウンド消費動向調査 | 訪日外客統計 | 出入国管理統計（船舶観光上陸許可） |
| 知りたいこと | 訪日客が**1人いくら使ったか** | 訪日客が**何人来たか** | そのうち**クルーズ客が何人か** |
| 公表の粒度 | 四半期 | 月 | 月 |
| ファイルの形 | 四半期ごとに別ファイル（10件） | 1ファイルに年別シート（24枚） | 月ごとに別ファイル |

3つ目が必要な理由は、**消費動向調査の単価と、訪日外客統計の人数が、同じ母集団を指していない**からです。

観光庁が国籍・地域別に公表している1人あたり旅行支出は、**クルーズ客を除いた「一般客」**のものです。一方 JNTO の訪日外客数には**クルーズ客が含まれます。** この2つをそのまま掛けると、消費総額が過大になります。

```
一般客数 ＝ JNTO 訪日外客数 − 船舶観光上陸許可（クルーズ客）
```

クルーズ客数は法務省の出入国管理統計から取得します。観光庁もこの統計を用いてクルーズ客数を推計していると注記しています。

:::caution この事例は「例示」です

本事例で算出する消費総額は、Kari の動作例として求める**試算値**です。観光庁の公表数値と完全には一致しません。手法の大枠を示すことが目的です。

:::

- 保存先となる作業フォルダーを決めます。左のナビパネルの「エクスプローラー」を右クリックし、「フォルダーを開く…」から指定します。本例では `データ分析2` を使っています。

- チャットセッションを開きます。3つの指示は**同じセッションで続けて**出します。

:::tip 同じページを別の目的で使う

観光庁のインバウンド消費動向調査のページは、[データダウンロード・ファイル名変更の自動化](/browserautomation/customdownload)でも扱っています。そちらは**規定のファイル名で保存すること**が目的でした。

このページでは、さらに一歩進めて**分析に使える1つのファイルに統合するところまで**を任せます。同じ取得元でも、**次に何をするか**で指示の形が変わります。

:::

## AI に作業を指示

- 観光庁のWebページからインバウンド消費動向調査データをダウンロードするため、以下のように AI に作業を指示します。

```text title="AI への指示"
観光庁のインバウンド消費動向調査のWebページ「https://www.mlit.go.jp/kankocho/tokei_hakusyo/gaikokujinshohidoko.html」を起点に、以下のようにファイルダウンロード・統合処理を実施する。

1. 「集計表」のセクションで、各四半期のExcelファイルを現在のフォルダーへダウンロードする。
  (1) ダウンロードリンクのラベルは「A-B月期」になっているが、該当年YYYYをページの構造で上位のサブセクションから正しく取得する。
  (2) ダウンロードURLから取得したExcelファイルを、「YYYY年A-B月期.xlsx」のように改名して保存する。もし元ファイルは旧XLSのファーマットの場合、適宜にXLSXフォーマットに変換する。
  (3) ダウンロードの対象は、2024年から直近までのファイルとする。
2. ダウンロードしたファイルを、一つのExcelファイルに統合する。
  (1) 元のExcelファイル「YYYY年A-B月期.xlsx」からシート「参考2」を抽出し、新規作成のExcelファイルにシート「YYYY年A-B月期_参考2」として挿入する。
  (2) 統合したExcelファイルを、「インバウンド消費動向調査統合_参考2.xlsx」として現在のフォルダーで保存する。
3. 各シートのB4セルに記載された期の表記が、シート名と一致することを確認して報告する。
```

![AI にインバウンド消費動向調査のダウンロードと統合を指示する](@site/docs/current/main/aidataanalysis/img/inbound_consumption_downloadprompt.png)

:::

:::tip なぜ「参考2」なのか

同じブックには `表2-1` `表3-1` `参考1` `参考2` など37枚のシートがあり、**どれを使うかで結果が変わります。**

| シート | 内容 |
| --- | --- |
| `表2-1` | 費目別の**購入率**と**購入者単価**（買った人の平均額） |
| `表3-1` | 1人あたり旅行消費単価（**パッケージツアー参加費の国内分を含まない**） |
| `参考2` | 費目別1人1回当たり旅行消費単価（**パッケージツアー参加費内訳含む**） |

観光庁の公表する消費総額が立脚しているのは **`参考2` の系列**です。`表2-1` の購入率と購入者単価を掛けて合計すると `表3-1` と一致しますが、**参加費の国内分が落ちるため1割ほど低く出ます。**

`参考2` の値は**全員平均の単価**です。購入率はすでに織り込まれているため、`表2-1` のように購入率を掛けると二重になります。

:::

- 次に、JNTOのWebページから訪日来客数データをダウンロードするため、以下のように AI に作業を指示します。

```text title="AI への指示"
JNTOの訪日外客統計のWebページ「https://www.jnto.go.jp/statistics/data/visitors-statistics/」で、時系列推移表
のセクションを見つけ、その配下で「国籍/月別 訪日外客数...」のExcelファイルを特定してダウンロードし、現在フォルダーで「国籍_月別_訪日外客数_通期.xlsx」として保存する。
```

![AI に JNTO の訪日外客統計のダウンロードを指示する](@site/docs/current/main/aidataanalysis/img/inbound_visit_downloadprompt.png)

- 最後に、法務省（出入国在留管理庁）の出入国管理統計のうち、船舶観光上陸許可（クルーズ客）の月次データを取得するように AI に作業を指示します。

```text title="AI への指示"
法務省（出入国在留管理庁）の出入国管理統計のうち、船舶観光上陸許可（クルーズ客）の月次データを、e-Statの検索結果ページ「https://www.e-stat.go.jp/stat-search/files?page=1&query=%E8%88%B9%E8%88%B6%E8%A6%B3%E5%85%89%E4%B8%8A%E9%99%B8%E8%A8%B1%E5%8F%AF&toukei=00250011&layout=dataset」を起点に、以下のようにダウンロード・統合する。

1. 検索結果から、月次の統計表をExcel形式で現在のフォルダーへダウンロードする。
  (1) 対象は、表題が「港別 船舶観光上陸許可を受けた外国人の国籍・地域」で、表番号が「YY-MM-04-4」形式（例：26-06-04-4）の月次表とする。表番号が「YY-00-15」などの年次表は対象外とする。
  (2) 検索結果は複数ページに分かれ、時系列順にも並んでいない。全ページを確認して対象を漏れなく拾う。
  (3) 対象期間は2024年1月から直近の公表月までとする。年月は、リンクのラベルではなく各データセットの「調査年月」から取得する。
  (4) ダウンロードしたファイルを「YYYY年MM月_船舶観光上陸許可.xlsx」と改名して保存する。保存後は拡張子を信用せず、ファイル先頭のバイトでExcelの実体であることを確認する。HTMLが保存された場合は、Excelのダウンロードリンクを取り直す。旧XLS形式であれば、XLSX形式に変換する。
2. ダウンロードしたファイルを、一つのExcelファイルに統合する。
  (1) 各ファイルの統計表のシートを、新規作成のExcelファイルに「YYYY年MM月」というシート名で、時系列順に挿入する。
  (2) 各シートの表中に記載された調査年月が、シート名と一致することを確認する。
  (3) 統合したExcelファイルを、「船舶観光上陸許可_国籍別_月次統合.xlsx」として現在のフォルダーで保存する。
3. 欠けている月、取得元のURL、形式の扱いを一覧で報告する。
```

![AI に法務省のクルーズ客データのダウンロードを指示する](@site/docs/current/main/aidataanalysis/img/inbound_cruisepassengers_downloadprompt.png)

この3つの指示の組み立て方には、次のポイントがあります。

| 指示のブロック | ねらい |
| --- | --- |
| 観光庁 1-(1) 年はページ構造から取る | **リンクのラベルには年が入っていません。** 「4-6月期」とだけ書かれたリンクが、年の見出しの下に並んでいます。どこから年を取るかを指示しないと、取り違えが起きます。 |
| 観光庁 1-(2) 旧形式の変換 | 観光庁のファイルは**年によって .xls と .xlsx が混在**します。後の統合で扱えるよう、形式をそろえさせます。 |
| 観光庁 1-(3) 対象期間の限定 | 「2024年から直近まで」と区切ります。全期間を取ると古い形式のファイルが増え、統合が複雑になります。 |
| 観光庁 2-(1) シート名の規則 | 統合先のシート名を「YYYY年A-B月期_参考2」と**指定します。** 名前を決めておかないと、どのシートがどの期のものか分からなくなります。 |
| 観光庁 3. B4セルの照合 | 年をページ構造から推定しているため、**ファイルの中身で裏を取らせます。** |
| JNTO：セクションの特定 | 「時系列推移表のセクションを見つけ、**その配下で**」と階層を指定します。ページ全体から探させると、別の表を拾います。 |
| JNTO：Excelファイルの特定 | 同じ表が **Excel と PDF の両方**で公開されています。「Excelファイルを特定して」と明示します。 |
| 法務省 1-(1) 表番号で絞る | 同じ表題で**月次表と年次表の両方**が出てきます。表番号の形式（`YY-MM-04-4` と `YY-00-15`）で見分けさせます。 |
| 法務省 1-(2) 全ページを確認 | e-Stat の検索結果は**複数ページに分かれ、時系列順に並んでいません。** 「全ページを確認して漏れなく」と明示しないと、取りこぼします。 |
| 法務省 1-(3) 年月は調査年月から | ここでも**ラベルではなくデータの属性**から年月を取らせます。観光庁と同じ考え方です。 |
| 法務省 3. 欠けている月の報告 | 月次で31件を集めるため、**抜けを検知できるようにします。** 1か月欠けても合計は一見それらしい値になります。 |

:::caution

**リンクのラベルだけで年を判断させないでください。** 観光庁のページでは「1-3月期」「4-6月期」というラベルが年ごとの見出しの下に繰り返し現れます。ラベルだけを見ると、どの年のものか区別がつきません。「ページの構造で上位のサブセクションから」と**どこを見るかを指定する**ことが、この指示の要です。

e-Stat 側も同じです。リンクのラベルではなく、データセットの「調査年月」から取らせます。

:::

## AI の作業結果をチャットセッションで確認

- まず消費動向調査の結果です。ダウンロードしたファイルの一覧と、統合結果が報告されます。

![インバウンド消費動向調査のダウンロードと統合の結果](@site/docs/current/main/aidataanalysis/img/inbound_consumption_downloadresult.png)


`インバウンド消費動向調査統合_参考2.xlsx` に、`2024年1-3月期_参考2` から `2026年4-6月期_参考2` までの**10シート**が時系列で格納されます。

画面は、指示3で求めた**B4セルの照合結果**です。シート名と、シート内に書かれた期の表記を1件ずつ突き合わせ、**10シートすべてが一致**したと報告されています。

> 判定は、B4の文字列を NFKC 正規化し空白・ダッシュ種別を揃えた上で、シート名から `_参考2` を除いた期表記が含まれるかで行いました。B4には期表記の後に `【確報】` ／ `【2次速報】` という公表段階の注記が付くため、完全一致ではなく前方の期表記部分の一致で確認しています。つまり**年・四半期の対応ずれは1件もありません**。

指示 1-(1) で「年はページ構造から取れ」と命じた部分が、**ファイルの中身と突き合わせて確かめられています。** ページの読み取りが正しかったことを、別の経路で裏付けた形です。

判定の方法まで説明されている点にも注目してください。**完全一致では判定できない**ことを見抜き、正規化してから前方一致で照合しています。「一致しました」という結論だけでなく、**どう照合したか**が書かれているため、人が妥当性を判断できます。

:::caution 期によって列構成が異なります

`参考2` のシートは、**2024・2025年が48列（国籍・地域21区分）、2026年が54列（24区分）**です。2026年からメキシコ・北欧・中東が追加されたためです。

横断比較する際は、**列位置ではなくヘッダー名で突き合わせる**必要があります。

:::

- 次に JNTO の結果です。**どうやって目的のファイルにたどり着いたか**が説明されます。

![JNTO 訪日外客統計のダウンロード結果](@site/docs/current/main/aidataanalysis/img/inbound_visit_downloadresult.png)

> `<h2>時系列推移表</h2>` から次の `<h2>` までを当該セクションとして切り出し、配下のリンクを列挙しました

切り出したセクションには5つのリンクがあり、そのうち**先頭の2件がまったく同じラベル**です。

| ラベル | ファイル |
| --- | --- |
| **国籍/月別 訪日外客数（2003年〜2026年）** | `20260916_1615-5.xlsx` ← 対象 |
| 国籍/月別 訪日外客数（2003年〜2026年） | `20260916_1615-4.pdf` |
| 国籍/目的別 訪日外客数（2004年〜2025年） | `20260819_1615-6.pdf` |
| ビジット・ジャパン事業開始以降の訪日客数の推移 | `20260819_1615-7.pdf` |
| 年別 訪日外客数、出国日本人数の推移 | `20260819_1615-8.pdf` |

> 「国籍/月別 訪日外客数」はxlsxとpdfの2件が**同一ラベル**で並んでいるため、**拡張子でExcel版を選別**しています。

**表示名が同じで中身が違う**という、人が見ても間違えやすい箇所です。AI は何を根拠に選んだかを明示しています。

成果物についても、消費動向調査と同じ確認が行われています。

> マジックバイト `504b0304`・Content-Type も `spreadsheetml.sheet` で真正のxlsxと確認できたため、形式変換は不要でした

`504b0304` は ZIP の署名で、`.xlsx` の実体は ZIP です。**署名と Content-Type の両方**で確認しています。

> 中身: **24シート**（`2026`, `2025`, … `2003` の年別）、各シートが「市場（総数／アジア計／韓国／中国／台湾…）×月別実数＋伸率」の構成

:::caution 2026年のシートは年の途中までです

> 2026年シートは1月から公表済み月までの**部分年データ**です

年単位で合計すると、**2026年だけ他の年と比較できない数字**になります。AI はファイル内の注記からこれを読み取って報告しています。年次比較をする分析では、この行の扱いを先に決めてください。

:::

## ダウンロードしたExcelファイルの情報を確認

- 左のエクスプローラーで、保存されたファイルを確認します。四半期ごとの10ファイル、月ごとのクルーズ客ファイル、2つの統合ファイル、JNTOのファイルが並びます。

![統合したインバウンド消費動向調査のExcelファイル](@site/docs/current/main/aidataanalysis/img/inbound_consumption_excel.png)

統合ファイルを開くと、下部のシートタブが `2024年1-3月期_参考2` から時系列に並んでいます。指示したシート名の規則がそのまま適用されています。

シートの中身は、**分析にそのまま使える形ではありません。**

- 1〜4行目は表題と期の表記で、データではありません
- 5行目に国籍（`全国籍･地域` `韓国` `台湾` `香港`…）、6行目に `消費単価` と `構成比` という**2段のヘッダー**です
- 国籍のセルは**横方向に結合**されており、その下に2列ずつぶら下がっています
- 行は7行目の `全体【A1】` の下に `宿泊費` `飲食費` `交通費` `娯楽等サービス費` `買物代` `その他` が並び、さらにその下に `航空（日本国内移動のみ）` `Japan Rail Pass` のような小費目がぶら下がる**3階層**です

`構成比` の列は、その費目が `全体` に占める割合です。`全体` の行は 100.0 になります。

このような多段ヘッダーの表は、次のページで[データコレクションの AI 解析](./parserawdata.md)にかけて、分析に使えるテーブルに変換します。

- JNTOのファイルも確認します。

![JNTO 訪日外客統計のExcelファイル](@site/docs/current/main/aidataanalysis/img/inbound_visit_excel.png)

シートタブが `2026` から `2003` まで年別に並びます。各シートは、A1に「2026年　訪日外客数（総数）」、3行目に注記、4行目に `1月` `伸率` `2月` `伸率` … という**月と伸率が交互に並ぶヘッダー**です。

行の方も入れ子になっています。`総数` の下に `アジア計`、その下に `韓国` `中国` `台湾` …、さらに `中東地域` の下に `イスラエル` `トルコ` `GCC6か国` がぶら下がります。**合計の行と内訳の行が同じ列に混在**しているため、そのまま集計すると二重計上になります。

- クルーズ客のファイルも確認します。

![統合した船舶観光上陸許可のExcelファイル](@site/docs/current/main/aidataanalysis/img/inbound_cruisepassengers_excel.png)

シートタブが `2024年01月` から月別に並びます。各シートは、1行目に表題「4−4　港別　船舶観光上陸許可を受けた外国人の国籍・地域」、3〜4行目に**都道府県名と港名の2段ヘッダー**、5行目から `総数` `アジア` と続いて個別の国籍・地域が並びます。

**B列が「全国／総数」**で、ここが本事例で使う全国の人数です。C列以降は港ごとの内訳で、**掲載される港は月によって変わります。**

:::caution 国籍の区分が JNTO と一致しません

クルーズ客のデータは `中国` `中国〔香港〕` `中国〔その他〕` のように区分されており、JNTO の `中国` `香港` とは**表記も粒度も違います。** 引き算で一般客数を求めるには、**国名の対応付けが必要**です。

この突き合わせは[データ結合のページ](./joindata.md)で扱います。

:::

:::tip 取得の時点では「そのままの形」で保存してよい

3つのファイルとも、分析には整形が必要な形をしています。しかし**この段階で整形する必要はありません。**

元の構造のまま保存しておけば、後から別の表（`参考1` や `表2-1` など）を使いたくなったときに、取得からやり直さずに済みます。整形は次の工程の仕事です。

:::

## Human-in-the-loop のポイント

AI に任せきりにせず、次の点は人が確認してください。

- **どのシートを使うかを自分で決める**  
消費動向調査のブックには37枚のシートがあり、**似た名前で中身の違う表**が並んでいます。`表2-1` と `参考2` では、算出される1人あたり支出が1割ほど違います。**何を分析したいかに応じて、使うシートを指定してください。**

- **年の割り当てを抜き取り確認する**  
リンクのラベルに年が入っていないため、**年はページの構造から推定された**ものです。本例では AI が各シートのB4セルと突き合わせて検証していますが、この検証を求めなかった場合は人が確かめる必要があります。年の境目にあたるファイル（1-3月期、10-12月期）を優先して開いてください。

- **ファイルが本当に Excel か確かめる**  
アクセス制限がかかると、Excel のかわりに HTML のエラーページが同じファイル名で保存されることがあります。本例のように**マジックバイトの確認**を依頼するか、保存後に数件を実際に開いてください。

- **月次データの抜けを確認する**  
クルーズ客のデータは月ごとに別ファイルで、e-Stat の検索結果は時系列順に並んでいません。**1か月欠けても合計は一見それらしい値になります。** 取得できた月の一覧を必ず読んでください。

- **期によって列構成が違うことを前提に設計する**  
2024/2025年は48列（21区分）、2026年は54列（24区分）です。**列位置で処理すると、ある期から静かにずれます。** ヘッダー名で突き合わせる方針を、次の工程の指示に含めてください。

- **速報と確報が混在していることを意識する**  
シートのB4セルには `【確報】` `【2次速報】` のような**公表段階の表記**が入っています。速報値は後から改定されます。直近の期を含む分析では、取得日を記録してください。

- **合計行と内訳行を区別する**  
JNTO・法務省の表はどちらも `総数` `アジア計` といった**集計行と個別の国・地域が同じ列**に並びます。そのまま合計すると二重に数えることになります。[東京不動産の事例](/aidataanalysis/tokyorealestate/populationcorrelation)で人口データの「地域階層」を扱ったのと同じ注意が必要です。

- **部分年データを年次比較に混ぜない**  
JNTOの2026年シートは年の途中までです。年合計で比較する場合は、除外するか、月数をそろえてください。

- **相手サイトの利用条件を守る**  
取得したデータの二次利用については、各機関の定める条件に従ってください。JNTOは出典の明記を求めています。

:::caution

使用する LLM により、ページ構造の読み取り方やファイル形式の確認方法が変わります。**何を根拠にそのファイルを選んだか**を報告させ、その説明が妥当かを確認してください。

:::
