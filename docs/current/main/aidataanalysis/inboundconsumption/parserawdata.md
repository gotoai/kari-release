# Kari の「AI解析」機能を活用してExcelファイルの解析を自動化させる

:::info 検証環境

本事例の手順は、以下の環境で動作を確認しています。

- **Kari**: バージョン 0.7.3 Windows
- **AI プロバイダー**: Anthropic Claude サブスクリプション
- **モデル**: Claude Opus 5.5 High

:::

## 説明

前のページで取得した3つの Excel ファイルは、人が見るために作られた表で、そのまますぐ分析に使える形にまだなっていません。

Excel ファイルのフォーマットの設計自由度が高い一方で、データの構造が複雑になることがあり、シートによってデータの組み立て方が違うこともあります。1つのシートでも、複数のテーブルデータを含むこともあります。

Kari の **「AI 解析」** は、この判断を AI に任せる機能です。シートの構成状況をもとに表の位置を見つけ、読み込み範囲を決めて、テーブルを作ります。

このページで扱う3つのファイルは、**それぞれ違う難しさ**を持っています。

| ファイル | シート数 | 難しいところ |
| --- | --- | --- |
| インバウンド消費動向調査統合_参考2 | 10 | 多段ヘッダー、3階層の行、**年によって列数が違う** |
| 国籍_月別_訪日外客数_通期 | 24 | 月と伸率が交互、**年によって構造が4通り** |
| 船舶観光上陸許可_国籍別_月次統合 | 31 | 都道府県と港の2段ヘッダー、**月によって列数が違う** |

:::tip CSV の AI 解析との違い

[生CSVデータの解析自動化](/aidataanalysis/tokyorealestate/parserawdata)でも同じ「AI 解析」を使いましたが、**送られる指示文が違います。**

CSV は「ファイル全体が1つの表」と決まっているため、指示は**型の変換**が中心でした。Excel では**表がどこにあるかの特定**から始まります。ブックに何枚シートがあり、各シートに表がいくつあるかは、開いてみるまで分かりません。

:::

## データコレクションを新規作成する

- 左のナビパネルの「データコレクション」にマウスを合わせ、「データコレクションを追加」をクリックします。

![データコレクションを追加する](@site/docs/current/main/aidataanalysis/img/inbound_analysis_createdatacollection.png)

本例では、**「データコレクション2」** を作成してデータ分析を進めます。

## Excelファイルを追加する

- 「データファイル」から「データファイルを追加…」を選びます。

![データファイルを追加する](@site/docs/current/main/aidataanalysis/img/inbound_analysis_adddatafile.png)

- 種類を選ぶダイアログで、**「Excel ファイルを追加」**を選びます。対応するのは `.xlsx` `.xlsm` `.xls` です。

![Excel ファイルを追加を選ぶ](@site/docs/current/main/aidataanalysis/img/inbound_analysis_adddatafile_excel.png)

- 3つのファイルを追加した状態です。

![3つの Excel ファイルが追加された状態](@site/docs/current/main/aidataanalysis/img/inbound_analysis_addeddatafile.png)

この時点では、まだテーブルはありません。**Excel の場合、ファイルを追加しただけでは表は作られません。** CSV と違って「どこが表か」が簡単なルールで決まらないためです。

## AI に解析を指示する

- データファイルを右クリックし、**「AI 解析」** を選びます。

![データファイルを右クリックして「AI 解析」を選ぶ](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile.png)

- 新しいチャットセッションが開き、**Excel 用の指示文が自動で入力されて送信されます。**

![Excel 用の AI 解析の指示文](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_prompt.png)

送られる指示文の要点は次のとおりです。

| 指示の要素 | ねらい |
| --- | --- |
| まず `dc_peek_file` でシート一覧 | **ブック全体の形を先に把握**させます。シートが何枚あるかも分からない状態から始まります。 |
| occupancy bands で表の位置を判断 | 行ごとの**セルの埋まり具合**を手がかりにします。空白のバンドは表の区切り、先頭行のセル数が極端に少ないバンドはタイトル行か結合ヘッダーです。 |
| Excel のテーブルオブジェクトがあればその範囲を信頼 | ブックに正式な「テーブル」が定義されていれば、**推測より確実**です。 |
| 続けて実際のセルを確認 | バンドだけで決めさせません。**中身を見て確かめる**手順が入っています。 |
| シートの領域ごとに1テーブル | 1つのシートに表が2つあれば、**テーブルも2つ**作らせます。 |
| 型はブックのものを使い、混在した列だけ変換 | Excel はセルに型を持っています。**本当に混ざっていた列だけ**を変換させます。 |

この指示文は**ファイルごとに自動生成**されます。**3つのファイルそれぞれで「AI 解析」を実行してください。**

:::caution

**AI 解析を実行すると、そのブックで作成済みのテーブルはすべて破棄されます。** 確認ダイアログが出ます。スクリプトを手で調整したあとに実行し直すと、その調整は失われます。

:::

## AI の解析結果メッセージを確認する

- まず消費動向調査の統合ファイルです。

![消費動向調査ファイルの解析結果](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_result1.png)

`参考2` のシートは**1枚につき表が1つ**です。したがって **10シート＝10テーブル**になります。スクリプトのパラメータも報告されます。

> `skiprows=4`（行1-4の表題・単位注記を飛ばす）、`nrows=45`（ヘッダー2行＋データ43行）、`usecols="B:AV"`（2024-2025）または `"B:BB"`（2026）で空の列Aを除外。

列の構成は次のとおりです。

- `費目区分1` `費目区分2` `費目区分3` の3列が、シートのB・C・D列にまたがる**費目の3段ラベル**
- 以降は国籍・地域ごとに2列ずつ `<地域>_消費単価`（円/人）と `<地域>_構成比`（%）
- 地域名は5行目で**2列結合**になっているため、`ffill`（前方補完）で組の2列目へ広げ、6行目の「消費単価／構成比」と連結

結合セルは、そのままでは1つ目の列にしか値が入りません。前方補完で2列目にも同じ地域名を配ることで、`韓国_消費単価` `韓国_構成比` のような**列名が作られています。**

:::caution 年によって列数が違います

> **地域区分がシートで異なります**：2024-2025の8シートは22区分（全国籍･地域＋21区分…）。2026の2シートは**25区分**で、メキシコ・北欧・中東が追加されています。そのため列幅が48→54列に広がっており、usecols を分けました。

表題そのものが `参考2 国籍･地域（21区分）別…` と `（24区分）別…` で違います（表題の数字は全国籍・地域を含みません）。**期をまたいで比較する際は、列位置ではなくヘッダー名で突き合わせてください。**

:::

:::tip ffill を「しなかった」判断にも注目してください

地域名には前方補完をかけた一方で、AI は `費目区分1` には**かけていません。**

> `費目区分1` は ffill していません。列Bの「日本滞在中の」「費目別支出」「【A1】」は結合セルではなく、**見出しを3行に折り返して別セルに入力したもの**だったため、埋めると誤った値が入ります。実質的な費目名は `費目区分2`（宿泊費・飲食費・交通費・娯楽等サービス費・買物代・その他）と `費目区分3`（内訳）に入っています。

見た目が似ている「結合セル」と「折り返して入力された見出し」を**区別して扱っている**箇所です。機械的に前方補完をかけていたら、`費目区分1` に意味のない値が埋まっていました。

:::

型変換についても報告があります。

> **2024年1-3月期のロシア2列**は全43行が `-`（調査値なし）でした。混在列として `pd.to_numeric(errors="coerce")` で数値化した結果、全行欠損となり、値の手がかりがないため Kari 上では text（VARCHAR）と表示されています。**空列として放置したのではなく、元データが全欠損です。**

なお「2024-2025は【確報】、2026は【2次速報】」という**速報段階の区別は行4の注記にあり、テーブルの列には取り込まれていません。**

- 次に JNTO の訪日外客統計です。

![訪日外客統計ファイルの解析結果](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_result2.png)

24シートすべてがテーブル化され、**24テーブル**になります。レイアウトの判断が、行単位で説明されます。

> - r1 タイトル（「〇〇年　訪日外客数（総数）」＋出典）
> - r2 空行
> - r3 注記（「＊本表で…」＋単位）
> - r4 ヘッダー（1月／伸率 …12月／伸率、累計／伸率）
> - r5〜 データ（市場＝総数・地域計・国）
> - 末尾2行 注記（出典明示、確定値／推計値の断り）

ここが、このページでいちばん読む価値のある一文です。

> **occupancy band 上は r3〜末尾が1つの帯でしたが、セルを見ると r3 は注記、r4 がヘッダー、末尾2行は注記なので、表本体は r5 からとしました。**

セルの埋まり具合だけを見れば、3行目から最終行までが**ひとつながりの表に見えます。** しかし中身を読めば、先頭は注記、最後の2行も注記です。**バンドの判断を、実際のセルで覆している**わけです。指示文に「続けて実際のセルを確認してください」と書かれているのは、このためです。

さらに、**年によって構造が4通りある**ことが報告されます。

| 年 | ラベル列 | 読み込み範囲 |
| --- | --- | --- |
| 2026〜2023 | A＝市場、B＝内訳 | r5〜r58（nrows=54, usecols=A:AB） |
| 2022〜2020 | A＝市場、B＝内訳 | r5〜r57（nrows=53, usecols=A:AB） |
| 2019〜2016 | A＝市場のみ | r5〜r55（nrows=51, usecols=A:AA） |
| 2015〜2003 | A＝市場のみ | r5〜r48（nrows=44, usecols=A:AA） |

> B列の「内訳」は、中東地域（イスラエル／トルコ／GCC6か国）や北欧地域（スウェーデン／デンマーク／ノルウェー／フィンランド）の内訳行にだけ値が入る列です。**2019年以前はこの入れ子がないため列自体がありません。**

24シートを「全部同じ」と決めつけていたら、2019年以前で列がずれていました。

この入れ子を2列にするために、AI は前方補完を使っています。そして、**その結果どう読むべきか**まで報告します。

> A列が空の内訳行に親が分かるよう `市場` を ffill し、`内訳` の全角空白インデントを strip しています。**内訳行は親の内部明細なので、`市場` で合計すると二重計上になります**（`内訳` が空の行だけが独立した市場です）。

集計時にどの行を使うべきかが、この一文で決まります。[データ結合のページ](./joindata.md)で実際に効いてきます。

年をまたいで扱う際の細かい差異も挙げられています。

- **2008・2009 のみ合計列のラベルが「年計」**（他年は「累計」）。シートの表記どおりにしてあるため、年を横断して結合する際はここだけ名前が違います
- **2026年は年途中**：9月〜12月が人数・伸率とも全欠損、7月・8月も一部の市場が空です。**数式が空で読まれたのではなく、まだ発生していないデータです**
- 2026年の脚注にある「斜体の数値は推計値である」という区別は、**セル書式でしか判別できないためテーブルには反映されていません**

- 最後にクルーズ客の統合ファイルです。

![クルーズ客ファイルの解析結果](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_result3.png)


31シートすべてがテーブル化され、**31テーブル**になります。月ごとに読み込み範囲と行数・列数が一覧で示されます。

列の構成は次のとおりです。

> `国籍・地域`（テキスト。「総数」「アジア」等の**地域小計行と国別行が混在、原表のまま**）、`全国_総数` および `福岡県_博多`、`沖縄県_那覇` のような **`県_港` 列**（すべて integer / BIGINT）。

列名を `県_港` にした理由も説明されています。

> 長崎県（佐世保・長崎）、沖縄県（石垣・那覇・平良）のように**同一県に複数港があり、県名だけでは一意にならない**ためです。港名だけでも一意ですが、県情報が失われます。

:::caution 月によって港の構成が変わります

> **港の構成は月ごとに異なります**（5港〜13港）。レイアウトは同一でも列が揃わないため、ご指示どおりシート横断の統合はしていません。

さらに、1か月だけの例外も報告されています。

> **2026年07月のみ関門が2港に分割**されており、`山口県_関門（下関）` と `福岡県_関門（門司）` の2列があります（福岡県が2列）。他の月は `山口県_関門（下関）` のみです。

本事例で使うのは **`全国_総数` だけ**なので影響しませんが、港別の分析をする場合は、**月ごとに列が変わる前提で設計**してください。

:::

型については、消費動向調査と対照的な報告になります。

> **型変換は1件も行っていません。** ブックが型を保持しており、31テーブル全てで国籍・地域列が text、人数列が BIGINT として読み込まれました。混在列はありませんでした。

このほか、判断に迷った点として次が挙げられています。

- **r2 の対象月を列にしていません。** 各シートの r2 に `2024-01-01` 形式で対象月が1セル入っていますが、**シート名（＝テーブル名の前置）が同じ月を表す**ため、ヘッダー扱いで飛ばしています
- **地域小計行の扱い**：「総数」「アジア」「ヨーロッパ」などの小計行が国別行と同じ列に並んでいます。**区分フラグ列は追加せず原表のまま**にしてあるため、集計時に二重計上しないよう注意が必要です
- 2026年04月の末尾に `無国籍` 行があり、データ行として含まれています

## AI の解析結果テーブルを確認する

- 消費動向調査のテーブルです。左のツリーに、シートごとに1つずつテーブルが並びます。

![消費動向調査から作成された10テーブル](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_tables1.png)

テーブル名は `2024年1-3月期_参考2.国籍地域別費目別消費単価` のように、**シート名に AI が付けた内容名が続く**形になります。

テーブルを開くと、`費目区分1` `費目区分2` `費目区分3` の3列に続いて、`全国籍・地域_消費単価` `全国籍・地域_構成比` `韓国_消費単価` `韓国_構成比` …と地域ごとに2列ずつ並びます。1行目が `全体【A1】` で、`消費単価` 211,088.99 円、`構成比` 100 です。

:::caution 階層ラベルは「見た目」のまま入っています

グリッドをよく見ると、`費目区分1` 列は上から「全体【A1】」「日本滞在中の」「費目別支出」「【A1】」と並び、5行目以降は `NULL` になります。

これは元の Excel で、**縦長の見出しが3行に折り返して別セルに入力されている**ためです。前の節で見たとおり、AI はここに前方補完をかけていません。**埋めると誤った値が入る**からです。

実質的な費目名は `費目区分2`（宿泊費・飲食費・交通費・娯楽等サービス費・買物代・その他）と `費目区分3`（その内訳）に入っています。本事例で使うのは `全体` の行と6つの大費目の行なので、`費目区分1` を分類として使う場面はありません。

:::

- 訪日外客統計のテーブルです。年ごとに1つ、24件が並びます。

![訪日外客統計から作成された24テーブル](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_tables2.png)

テーブル名は `2026.月別市場別` のように、**年がテーブル名の前置**になります。列は `市場`〔, `内訳`〕, `1月`, `1月_伸率`, …, `12月`, `12月_伸率`, `累計`, `累計_伸率` です。人数は integer、伸率は number になっています。

グリッドでは、`総数` `アジア計` `韓国` …が `市場` 列に並び、`内訳` は `NULL` です。14行目の `中東地域` だけは `内訳` が `NULL` のまま地域計を表し、続く3行は `市場` が `中東地域` のまま `内訳` に `イスラエル` `トルコ` `GCC6か国` が入ります。**入れ子の構造が2列で表現されています。**

この対応付けは[データ結合のページ](./joindata.md)で扱います。

## Human-in-the-loop のポイント

AI に任せきりにせず、次の点は人が確認してください。

- **テーブル数が想定と合うか数える**  
`参考2` は1シート1表なので**10テーブル**、訪日外客統計は**24テーブル**、クルーズ客は**31テーブル**になるはずです。数が合わない場合、表の切り出しに失敗しています。

- **表の切り出し位置を数件だけ開いて確かめる**  
AI は occupancy band と実際のセルを突き合わせて範囲を決めていますが、**最終的な判断は推定**です。特に「末尾2行は注記」のような末端の判断は、1件開いて目で確かめる価値があります。最終行に注記が混ざっていれば、集計値が狂います。

- **シートごとに構造が違う前提で確認する**  
消費動向調査は2026年から区分が3つ増え、訪日外客統計は年によってラベル列の本数が変わり、クルーズ客は月によって港の列が変わります。**「全シート同じ」と報告されていても、その根拠を読んでください。**

- **「-」の意味を確認する**  
同じ「-」が、ファイルによって「該当なし」とも「算出不能」とも読めます。**NULL として同じに見えても、集計では区別が必要です。** 平均を取るときに除外してよいのか、0 とみなすべきなのかは、元データの注記を読んで決めてください。

- **階層ラベルの列を点検する**  
`費目区分1` のように、見出しを折り返して入力した結果がそのまま列になります。AI が前方補完をかけたか、かけなかったかを含め、分析の前に**この列が分類として使える状態か**を確認してください。

- **合計行と内訳行を区別する**  
訪日外客統計とクルーズ客のどちらも、`総数` `アジア計` と個別の国が同じ列に並びます。そのまま合計すると二重に数えます。[人口データの事例](/aidataanalysis/tokyorealestate/populationcorrelation)と同じ構図です。

- **AI 解析のやり直しは破壊的である**  
再実行すると既存のテーブルは破棄されます。スクリプトを調整した場合は、先に控えを取ってください。

:::caution

使用する LLM により、表の切り出し位置やテーブルの分け方が変わります。**なぜその範囲にしたのか**の説明を読み、納得できない箇所は解析スクリプトを直接確認してください。

:::
