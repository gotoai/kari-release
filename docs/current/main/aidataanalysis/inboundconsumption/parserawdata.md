# Kari の「AI解析」機能を活用してExcelファイルの解析を自動化させる

:::info 検証環境

本事例の手順は、以下の環境で動作を確認しています。

- **Kari**: バージョン 0.7.3 Windows
- **AI プロバイダー**: Anthropic Claude サブスクリプション
- **モデル**: Claude Opus 5.5 High

:::

## 説明

前のページで取得した2つの Excel ファイルは、人が見るために作られた表で、そのまますぐ分析に使える形にまだなっていません。

Excel ファイルのフォーマットの設計自由度が高い一方で、データの構造が複雑になることがあり、シートによってデータの組み立て方が違うこともあります。1つのシートでも、複数のテーブルデータを含むこともあります。

Kari の **「AI 解析」** は、この判断を AI に任せる機能です。シートの構成状況をもとに表の位置を見つけ、読み込み範囲を決めて、テーブルを作ります。

:::tip CSV の AI 解析との違い

[生CSVデータの解析自動化](/aidataanalysis/tokyorealestate/parserawdata)でも同じ「AI 解析」を使いましたが、**送られる指示文が違います。**

CSV は「ファイル全体が1つの表」と決まっているため、指示は**型の変換**が中心でした。Excel では**表がどこにあるかの特定**から始まります。ブックに何枚シートがあり、各シートに表がいくつあるかは、開いてみるまで分かりません。

:::

## データコレクションを新規作成する

- 左のナビパネルの「データコレクション」にマウスを合わせ、「データコレクションを追加」をクリックします。

![データコレクションを追加する](@site/docs/current/main/aidataanalysis/img/inbound_analysis_createdatacollection.png)

本例では、**「データコレクション2」** を作成してデータ分析を進めます。

## Excelファイルを追加する

- 「データファイル」から「データファイルを追加…」を選びます。

![データファイルを追加する](@site/docs/current/main/aidataanalysis/img/inbound_analysis_adddatafile.png)

- 種類を選ぶダイアログで、**「Excel ファイルを追加」**を選びます。対応するのは `.xlsx` `.xlsm` `.xls` です。

![Excel ファイルを追加を選ぶ](@site/docs/current/main/aidataanalysis/img/inbound_analysis_adddatafile_excel.png)

- 2つのファイルを追加した状態です。

![2つの Excel ファイルが追加された状態](@site/docs/current/main/aidataanalysis/img/inbound_analysis_addeddatafile.png)

この時点では、まだテーブルはありません。**Excel の場合、ファイルを追加しただけでは表は作られません。** CSV と違って「どこが表か」が簡単なルールで決まらないためです。

## AI に解析を指示する

- データファイルを右クリックし、**「AI 解析」** を選びます。

![データファイルを右クリックして「AI 解析」を選ぶ](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile.png)

- 新しいチャットセッションが開き、**Excel 用の指示文が自動で入力されて送信されます。**

![Excel 用の AI 解析の指示文](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_prompt.png)

送られる指示文の要点は次のとおりです。

| 指示の要素 | ねらい |
| --- | --- |
| まず `dc_peek_file` でシート一覧 | **ブック全体の形を先に把握**させます。シートが何枚あるかも分からない状態から始まります。 |
| occupancy bands で表の位置を判断 | 行ごとの**セルの埋まり具合**を手がかりにします。空白のバンドは表の区切り、先頭行のセル数が極端に少ないバンドはタイトル行か結合ヘッダーです。 |
| Excel のテーブルオブジェクトがあればその範囲を信頼 | ブックに正式な「テーブル」が定義されていれば、**推測より確実**です。 |
| 続けて実際のセルを確認 | バンドだけで決めさせません。**中身を見て確かめる**手順が入っています。 |
| シートの領域ごとに1テーブル | 1つのシートに表が2つあれば、**テーブルも2つ**作らせます。 |
| 型はブックのものを使い、混在した列だけ変換 | Excel はセルに型を持っています。**本当に混ざっていた列だけ**を変換させます。 |

:::caution

**AI 解析を実行すると、そのブックで作成済みのテーブルはすべて破棄されます。** 確認ダイアログが出ます。スクリプトを手で調整したあとに実行し直すと、その調整は失われます。

:::

## AI の解析結果メッセージを確認する

- まず消費動向調査の統合ファイルです。

![消費動向調査ファイルの解析結果](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_result1.png)

> ブック全10シートがすべて同じ構成でした。各シートに表が2つあるので、**シート×2＝20テーブル**です。

1シートに表が2つある、という判断が最初に報告されます。根拠も示されています。

> バンドの読み方：行2は1セルのみ＝表タイトル、行4は期と単位の注記、**行52の空白が2つの表の区切り**です。Excel のテーブルオブジェクトは記録されていませんでした。

読み込み範囲は、**年によって列の終わりが違います。**

| シート | テーブル | 読み込み範囲 |
| --- | --- | --- |
| 2024年1-3月期 〜 2025年10-12月期（8シート） | 購入率 | ヘッダー 行5-6、データ 行7-51、列 **B:AV** |
| 同上 | 購入者単価 | ヘッダー 行53-54、データ 行55-99、列 **B:AV** |
| 2026年1-3月期、2026年4-6月期 | 購入率 | ヘッダー 行5-6、データ 行7-51、列 **B:BB** |
| 同上 | 購入者単価 | ヘッダー 行53-54、データ 行55-99、列 **B:BB** |

列の構成についても説明されています。

> 以降は国籍・地域ごとに2列ずつ：`<地域>_回答数`（integer）、`<地域>_購入率`（number, %）…。**地域名は行5/行53で2列結合になっているため `ffill` で列対に配っています。**

結合セルは、そのままでは1つ目の列にしか値が入りません。`ffill`（前方補完）で2列目にも同じ地域名を配ることで、`韓国_回答数` `韓国_購入率` のような**列名が作られています。**

型変換も、必要な列だけに絞られています。

> ブックが型を持っているので、**該当なしを表す「-」が混ざって文字列になった列だけ** `pd.to_numeric(errors="coerce")` で数値化しました（「-」は NaN）。購入者単価の表では毎期15〜21列が該当、購入率の表では2024年1-3月期のロシア2列のみです。

そして、前のページで予告されていた**列数の違いの正体**が明かされます。

> **2026年の2シートは区分が増えています。** 2024〜2025年は22区分（全国籍・地域＋21）ですが、2026年の2期は25区分で、`メキシコ` `北欧` `中東` が追加されています。シート幅が48列→54列になる理由です。期をまたいで比較する際はご注意ください。

- 次に JNTO の訪日外客統計です。

![訪日外客統計ファイルの解析結果](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_result2.png)

> 24シートすべてをテーブル化し、全テーブルでスクリプトを実行しました。未処理のテーブルはありません。

レイアウトの判断が、行単位で説明されています。

> - r1 タイトル（「〇〇年　訪日外客数（総数）」＋出典）
> - r2 空行
> - r3 注記（「＊本表で…」＋単位）
> - r4 ヘッダー（1月／伸率 …12月／伸率、累計／伸率）
> - r5〜 データ（市場＝総数・地域計・国）
> - 末尾2行 注記（出典明示、確定値／推計値の断り）

ここが、このページでいちばん読む価値のある一文です。

> **occupancy band 上は r3〜末尾が1つの帯でしたが、セルを見ると r3 は注記、r4 がヘッダー、末尾2行は注記なので、表本体は r5 からとしました。**

セルの埋まり具合だけを見れば、3行目から最終行までが**ひとつながりの表に見えます。** しかし中身を読めば、先頭は注記、最後の2行も注記です。**バンドの判断を、実際のセルで覆している**わけです。指示文に「続けて実際のセルを確認してください」と書かれているのは、このためです。

さらに、**年によって構造が4通りある**ことが報告されます。

| 年 | ラベル列 | 読み込み範囲 |
| --- | --- | --- |
| 2026〜2023 | A＝市場、B＝内訳 | r5〜r58（nrows=54, usecols=A:AB） |
| 2022〜2020 | A＝市場、B＝内訳 | r5〜r57（nrows=53, usecols=A:AB） |
| 2019〜2016 | A＝市場のみ | r5〜r55（nrows=51, usecols=A:AA） |
| 2015〜2003 | A＝市場のみ | r5〜r48（nrows=44, usecols=A:AA） |

> B列の「内訳」は、中東地域（イスラエル／トルコ／GCC6か国）や北欧地域（スウェーデン／デンマーク／ノルウェー／フィンランド）の内訳行にだけ値が入る列です。**2019年以前はこの入れ子がないため列自体がありません。**

24シートを「全部同じ」と決めつけていたら、2019年以前で列がずれていました。

## AI の解析結果テーブルを確認する

- 消費動向調査のテーブルです。左のツリーに、シートごとに2つずつテーブルが並びます。

![消費動向調査から作成された20テーブル](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_tables1.png)

`2024年1-3月期_表2-1.購入率` `2024年1-3月期_表2-1.購入者単価` …と、**シート名＋表の内容**という名前が付いています。シート名は自動で先頭に付くため、AI は「購入率」「購入者単価」という**内容を表す部分だけ**を名付けています。

テーブルを開くと、`調査項目1` `調査項目2` `調査項目3` の3列に続いて、地域ごとの列が並びます。元の表の**3階層のラベル**が、そのまま3列になっています。

:::caution 階層ラベルは「見た目」のまま入っています

グリッドをよく見ると、`調査項目1` 列は上から「旅行前支出」「【A1】」`NULL`「日本滞在中の」「費目別支出」「【A1】」と並びます。

これは元の Excel で、**縦長のラベルが複数のセルに分けて書かれている**ためです。「旅行前支出【A1】」という1つの見出しが、セル2つに分かれて入力されています。分析に使うには、**この列を人の目で確認して組み立て直す**必要があります。AI 解析はセルの配置を忠実に再現しますが、**見た目のための分割までは解釈しません。**

:::

- 訪日外客統計のテーブルです。年ごとに1つ、24件が並びます。

![訪日外客統計から作成された24テーブル](@site/docs/current/main/aidataanalysis/img/inbound_analysis_parsedatafile_tables2.png)

列は `市場`〔, `内訳`〕, `1月`, `1月_伸率`, …, `12月`, `12月_伸率`, `累計`, `累計_伸率` です。人数は整数、伸率は小数になっています。

グリッドでは、`総数` `アジア計` `韓国` …と `市場` 列に並び、`中東地域` の次の3行は `市場` が `NULL` で `内訳` に `イスラエル` `トルコ` `GCC6か国` が入ります。**入れ子の構造が2列で表現されています。**

型変換についても、重要な報告があります。

> 実際に効いたのは 2021〜2023 の伸率列で、「前年が0のため伸率を『-』と表記」したセルが混在していました。**この『-』は欠損（NULL）になります** — **0% ではなく「算出不能」の意味なので、集計時はご注意ください。**

同じ「-」でも、消費動向調査では**「該当なし」**、訪日外客統計では**「前年が0で計算不能」**と意味が違います。どちらも NULL になりますが、**集計での扱い方は変わります。**

最後に申し送りがあります。

> **2026年は通年ではありません。** 行によって埋まっている月が違い、総数・主要国などは8月まで、アジア計・マカオ…

前のページで「2026年は部分年データ」と報告されていましたが、ここではさらに踏み込んで、**行によって埋まっている月が違う**ことが分かりました。年単位の集計だけでなく、**月単位の比較でも行ごとに期間が揃っていません。**

## Human-in-the-loop のポイント

AI に任せきりにせず、次の点は人が確認してください。

- **表の切り出し位置を数件だけ開いて確かめる**  
AI は occupancy band と実際のセルを突き合わせて範囲を決めていますが、**最終的な判断は推定**です。特に「末尾2行は注記」のような末端の判断は、1件開いて目で確かめる価値があります。最終行に注記が混ざっていれば、集計値が狂います。

- **シートごとに構造が違う前提で確認する**  
消費動向調査は2026年から区分が3つ増え、訪日外客統計は年によってラベル列の本数が変わります。**「全シート同じ」と報告されていても、その根拠を読んでください。** 本例では両方とも、AI が違いを見つけて報告しています。

- **「-」の意味を確認する**  
同じ「-」が、ファイルによって「該当なし」とも「算出不能」とも読めます。**NULL として同じに見えても、集計では区別が必要です。** 平均を取るときに除外してよいのか、0 とみなすべきなのかは、元データの注記を読んで決めてください。

- **階層ラベルの列を点検する**  
`調査項目1` のように、見た目のために分割されたラベルがそのまま列になります。分析の前に、**この列が分類として使える状態か**を確認してください。

- **合計行と内訳行を区別する**  
訪日外客統計の `総数` `アジア計` `ヨーロッパ計` と、個別の国が同じ `市場` 列に並びます。そのまま合計すると二重に数えます。[人口データの事例](/aidataanalysis/tokyorealestate/populationcorrelation)と同じ構図です。

- **部分期間の行を把握する**  
2026年のシートは行によって埋まっている月が違います。**月をそろえずに年計や前年比を出すと、見かけ上の減少になります。**

- **AI 解析のやり直しは破壊的である**  
再実行すると既存のテーブルは破棄されます。スクリプトを調整した場合は、先に控えを取ってください。

:::caution

使用する LLM により、表の切り出し位置やテーブルの分け方が変わります。**なぜその範囲にしたのか**の説明を読み、納得できない箇所は解析スクリプトを直接確認してください。

:::
