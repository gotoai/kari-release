# AI によりデータの結合処理、ファクトテーブルの作成を自動化させる

:::info 検証環境

本事例の手順は、以下の環境で動作を確認しています。

- **Kari**: バージョン 0.7.3 Windows
- **AI プロバイダー**: Anthropic Claude サブスクリプション
- **モデル**: Claude Opus 5.5 High

:::

## 説明
データ分析において多くの場合は、1つの分析の目的のために異なるデータファイルを結合し、1つのデータのかたまりを作ります。例えば、「国籍・地域別のインバウンド消費総額」を試算するために、前のページで取得したインバウンド消費動向調査データと、訪日外客数データを結合することが必要です。なぜならば、計算のために必要な情報は、異なるデータに分かれているからです。

ここで大事なのは、「データ整合性」という概念です。過去に日本へ訪問した外国観光客の人数および消費金額は、実態としては同時に存在する情報です。しかし、調査手段、データの取得性などの制約事項により、あるいはデータ保持上の利便性などの理由で、こういった本来は一体となった情報は、今のように異なるデータとして断片的に収集・保存されています。複数のデータ断片から、もともとの情報のかたまりを正しく復元できることを、「データの整合性がとれている」といいます。

結合の際に、データのキーと、データの属性を定義します。何をもとに結合し、何を主な情報処理の対象とするかを決めるわけです。しばしば、全ての後続のデータ処理を準備するため、あらかじめ1つの網羅的な結合テーブルを作成します。こういう結合テーブルを「ファクトテーブル」と呼ぶことがあります。

この事例では、「国籍・地域」と「年月」をキーとし、ほかのデータカラムを属性とし、1つのファクトテーブルの作成を AI に任せます。

## AI に作業を指示

- 前のページで作成した44個のテーブル（消費動向調査20＋訪日外客統計24）を入力として、キー・粒度・属性・欠損の扱いをまとめて指示します。

```text title="AI への指示"
データコレクション「データコレクション2」でのデータテーブルを用いて、ファクトテーブルを作成し、データフローとして保存する。

1. インバウンド消費動向調査データと訪日外客数データを結合する。
  (1) 結合のキーは、「国籍・地域」と「年月」とする。「国籍・地域」以外の粒度の集計を除外する。
  (2) インプットテーブルでのヘッダーにキーがタグとして存在する場合、必要に応じて元の情報をキーと付随情報を分けた上で処理する。
  (3) インバウンド消費動向調査データは月単位になっていないため、調査期間に含まれた全ての月では同じ情報を持つことを見なして処理する。
  (4) 「国籍・地域」のキー対象はインバウンド消費動向調査データに含まれたものとする。
  (5) 集計の「年月」の開始時期は2024年1月とする。
  (6) 下記のコラムをファクトテーブルの属性データとする：
    - 来訪者数 (＊注意：元データに来訪者数を示す明確なヘッダーがないため、対応する月により正しく識別すること)
    - 日本滞在中の費目別支出費用の購入者単価と購入率。以下の項目ではそれぞれ、購入者単価と購入率の2つの属性をもつ：
      - 宿泊費
      - 飲食費
      - 交通費
      - 娯楽等サービス費
      - 買物代
      - その他  
  (7) データが欠損する場合、Null値を結合テーブルに入れる。

 2. 結合したテーブルをデータフロー「インバウンドファクトデータ」として保存する。
```

![AI にファクトテーブルの作成を指示する](@site/docs/current/main/aidataanalysis/img/inbound_joindata_prompt.png)

この指示の組み立て方には、次のポイントがあります。

| 指示のブロック | ねらい |
| --- | --- |
| 1-(1) キーと粒度 | 結合キーを先に確定させ、**「国籍・地域」以外の粒度を除外**させます。両方のデータに合計行（全国籍・地域、総数、アジア計…）が混ざっているため、これを書かないと**合計と個別が同じ列に並んだまま結合**されます。 |
| 1-(2) ヘッダーのタグ分離 | 消費動向調査は `韓国_購入者単価` のように、**ヘッダーにキーが埋まっています。** 列名を分解してキーと指標に分ける、という方針だけを与えます。 |
| 1-(3) 四半期の扱い | 消費側は四半期、外客数側は月です。**粒度が違うものを結合するときの規則**を決めておかないと、AI が独自に按分したり、四半期の行だけ残したりします。 |
| 1-(4) キー対象の基準 | どちらのデータに合わせるかを決めます。**消費動向調査側を基準**とすることで、調査対象でない国が混ざりません。 |
| 1-(6) 来訪者数の注意書き | 訪日外客統計の列は `1月` `1月_伸率` `累計` が並び、**「来訪者数」という列名はありません。** 何をもって人数とみなすかを補足しています。 |
| 1-(7) 欠損の扱い | 結合できなかった組み合わせを **Null で埋める**と指定します。行を落とすか Null を入れるかで、後続の集計が変わります。 |

:::caution

**粒度の除外を指示に含めてください。** インバウンド消費動向調査には「全国籍・地域」「中東」「北欧」、訪日外客統計には「総数」「アジア計」「ヨーロッパ計」といった**合計行**があります。これらをキーから除外しないと、個別の国と合計が同じ列に並び、**合計すると二重に数えることになります。**

:::

## AI の作業結果を確認する

![ファクトテーブル作成の結果報告](@site/docs/current/main/aidataanalysis/img/inbound_joindata_chatresult.png)

> データフロー「**インバウンドファクトデータ**」を保存しました。**672行 ＝ 21国籍・地域 × 32ヶ月（2024-01〜2026-08）**、キー重複ゼロ。

行数が **21 × 32 ＝ 672** と分解して示され、**キーの重複がゼロ**であることも報告されています。結合処理で最も起きやすい失敗は「キーが重複して行が増える」ことなので、ここが確認されているのは重要です。

列構成は次のとおりです。

| 列 | 内容 |
| --- | --- |
| 年月 | `YYYY-MM`（結合キー） |
| 国籍・地域 | 結合キー |
| 調査期間 | 消費動向調査の出典四半期（**値の由来を残すため付加**） |
| 来訪者数 | 訪日外客数 |
| 宿泊費／飲食費／交通費／娯楽等サービス費／買物代／その他 × 購入者単価・購入率 | 12列 |

指示になかった **「調査期間」列が追加**されている点に注目してください。四半期の値を月に展開すると、その値がどの調査期間から来たのかが分からなくなります。AI はこれを**由来を残すため**に列として持たせました。

### 処理の要点

AI は4つの処理について、何をどう判断したかを説明しています。

**1. ヘッダーのタグ分離**

> 消費動向調査は `韓国_購入者単価` のようにヘッダーにキーが埋まっているため、`国籍・地域`（キー）と指標（付随情報）に分解して**縦持ちへ変換**し、属性12列に再展開しました。

前のページで、結合ヘッダーを `ffill` で配った結果 `韓国_回答数` `韓国_購入率` という列名ができていました。**この列名の中にキー（国籍）が入っている**ため、そのままでは結合できません。いったん縦持ち（1行＝1つの国×1つの指標）に崩してから、属性12列に組み直しています。

**2. 来訪者数の識別**

> 訪日外客数側は `1月` ／ `1月_伸率` ／ `累計` が並びます。明示ヘッダーがないため、**素の `N月` 列を来訪者数と識別**（`_伸率` は伸び率、`累計` は年計なので除外）し、テーブル名の年と組み合わせて `年月` を生成しました。

`累計` を除外している点が効いています。これを人数として拾うと、年計が月の値として紛れ込みます。

**3. 四半期→月展開**

> `2024年1-3月期` の値を 2024-01／02／03 に**同一値で複製**。確認したとおり、**同一四半期内の3ヶ月は支出属性が同値、来訪者数のみ月変動します。**

これが、このファクトテーブルを読むうえで**最も重要な性質**です。詳しくは次の節で実際の値を見ます。

**4. 粒度の除外**

> 調査側の `全国籍・地域`（全体計）、`中東`・`北欧`（地域計）、`その他`（残余）をキーから除外。外客数側は `内訳` 行（イスラエル・GCC6か国等）を落とし、`総数`・`アジア計` 等は対象国リストで除外。**`豪州` → `オーストラリア` の表記差をマッピング**しました。行方向も、`調査項目3` が埋まった内訳行（新幹線、テーマパーク、化粧品…）を落として費目レベルのみ採用しています。

ここで3種類の作業が同時に行われています。

- **列方向の粒度除外** — 両方のデータから合計行を落とす
- **表記差の吸収** — 同じ国が `豪州` と `オーストラリア` で書かれている。マッピングしないと結合できず、行が消えます
- **行方向の粒度除外** — 前のページで見た `調査項目3`（新幹線、テーマパークなど）が埋まった**内訳行**を落とし、費目レベル（宿泊費・飲食費…）だけを採用

## ファクトテーブルを確認する

- 作成されたデータフローを開きます。

![作成されたインバウンドファクトデータ](@site/docs/current/main/aidataanalysis/img/inbound_joindata_tableresult.png)

1行が「ある国籍・地域の、ある月」です。左から `年月` `国籍・地域` `調査期間` `来訪者数` と続き、以降が費目ごとの `購入者単価` と `購入率` です。**分析にそのまま使える形**になりました。

:::caution 同じ四半期の3ヶ月は、支出の値が同一です

グリッドで **2026-01 のインド**（506行目付近）と **2026-02 のインド**（527行目付近）を見比べてください。

| | 2026-01 インド | 2026-02 インド |
| --- | --- | --- |
| 来訪者数 | 18,533 | **15,859** |
| 宿泊費_購入者単価 | 92,001.9629 | 92,001.9629 |
| 宿泊費_購入率 | 71.4677 | 71.4677 |
| 飲食費_購入者単価 | 41,612.7519 | 41,612.7519 |

**来訪者数だけが変わり、支出の属性はすべて同じ値**です。消費動向調査が四半期単位でしか公表されていないため、1-3月期の値を1月・2月・3月に複製しているからです。

これは誤りではなく、指示 1-(3) のとおりの処理です。ただし**月ごとの支出の変動を分析することはできません。** 月単位で動くのは来訪者数だけです。消費総額を月次で試算する場合、**変動要因は人数のみ**になります。

:::

`調査期間` 列に `2026年1-3月期` が残っているため、**どの四半期の値が複製されたものか**を後から確認できます。

## Human-in-the-loop のポイント

AI に任せきりにせず、次の点は人が確認してください。

- **行数の内訳を検算する**  
672行 ＝ 21国籍・地域 × 32ヶ月、と分解されています。**掛け算が合うか**を確かめてください。合わない場合はキーの重複か、結合漏れが起きています。「キー重複ゼロ」の報告も併せて読んでください。

- **四半期の値が複製されていることを常に意識する**  
支出属性は同一四半期内で同じ値です。**月次の支出の増減を論じることはできません。** 月単位で動くのは来訪者数だけです。四半期をまたぐ比較に限定してください。

- **除外された粒度の一覧を確認する**  
「全国籍・地域」「中東」「北欧」「その他」「総数」「アジア計」「内訳行」が落とされています。**自分が分析したい対象が、この除外に含まれていないか**を確認してください。たとえば中東全体を見たい場合、このファクトテーブルには入っていません。

- **表記差のマッピングを点検する**  
`豪州` → `オーストラリア` のマッピングが行われました。**他にも表記が違う国がないか**を確認してください。マッピング漏れがあると、その国は結合されずに Null になるか、行ごと消えます。21国籍・地域という数が期待どおりかを確かめるのが確実です。

- **期間の端を確認する**  
2024-01 から **2026-08** までです。終わりが8月なのは、訪日外客統計の2026年シートが8月までしか埋まっていないためです。**最後の数ヶ月は、国によってデータの有無が違う可能性があります。**

- **Null の由来を区別する**  
Null には複数の由来があります。結合できなかった組み合わせ、元データが「-」だったセル、そもそも公表されていない月。**集計の際、Null を0とみなすか除外するかで結果が変わります。**

- **「調査期間」列を捨てない**  
値の由来を示す唯一の手がかりです。後続の処理でこの列を落とすと、**複製された値かどうかが分からなくなります。**

:::caution

使用する LLM により、粒度の除外や表記差の扱いが変わります。**何を除外し、何をマッピングしたか**の報告を必ず読み、意図と一致しているかを確認してください。報告されていない除外があれば、行数が合わなくなります。

:::
