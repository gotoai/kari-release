# 概要

## ユースケースの説明

ビジネスの現場で知りたい数字は、**1つのファイルの中に揃っていないことがほとんど**です。必要な情報は複数の機関がそれぞれの都合で公表しており、粒度も形式も公表のタイミングも違います。

さらに厄介なのは、**知りたい数字そのものが公表されていない**場合です。本事例で扱う「国籍・地域別のインバウンド消費総額」も、どこにも公表されていません。単価と人数を別々の機関から取ってきて、掛け合わせて**試算する**しかありません。

従来の進め方では、この準備だけで大きな工数がかかります。Excel の表から数字を取り出し、粒度をそろえ、国名の表記差を吸収し、結合する——そして仮説を変えるたびに、同じ作業をやり直すことになります。

Kari の AI エージェントを活用すれば、**取得から解析、結合、試算、可視化、示唆出しまでを一貫して任せられます。** 処理はすべてデータフローとして残るため、条件を変えた再実行も短時間で済みます。本事例を通して、**複数の出所にまたがるデータ分析**がどこまで自動化できるかを確かめてください。

## シナリオ

インバウンド需要をビジネス機会として捉える立場から、**訪日外国人の消費動向**を分析します。検証する問いは、たとえば次のようなものです。

- どの国籍・地域から、どれだけの人が来ているか。その構成は変化しているか
- 1人あたりの支出額は、国籍・地域によってどう違うか
- 消費総額はどう推移しているか。**その増減を動かしているのは何か**
- 来訪者数が伸びている市場は、消費額でも伸びているか

最後の問いが、この事例の要点です。**人数と金額は、必ずしも同じ方向に動きません。** 来訪者数だけを見て市場を評価すると、判断を誤ります。

## 扱うデータの性質

本事例では、**2つの機関が公表する、性質の異なるデータ**を結合します。分析を始める前に、それぞれが何であるかを押さえてください。

| | インバウンド消費動向調査 | 訪日外客統計 |
| --- | --- | --- |
| 公表元 | 観光庁（国土交通省） | 日本政府観光局（JNTO） |
| 何を表すか | 訪日客が**何にいくら使ったか** | 訪日客が**何人来たか** |
| データの性格 | **調査（アンケート）の集計** | 出入国の統計 |
| 公表の粒度 | **四半期** | **月** |
| 公表のタイミング | 遅い（四半期ごと、速報→確報） | 早い（翌月） |
| ファイルの形 | 期ごとに別ファイル | 1ファイルに年別シート |

消費動向調査のデータには **「回答数」** という列があります。これが何人の回答を集計したものかを示しており、**回答者の集計である**ことが列の構成そのものから読み取れます。

:::caution 分析の前に押さえておきたい4点

**1. 粒度が違うものを掛け合わせています。**

消費動向調査は四半期、訪日外客統計は月です。本事例では、**四半期の単価を同じ四半期の各月に複製**して結合しています。そのため、**消費総額試算値の月ごとの変動は、来訪者数の変動のみに由来します。** 「この月に単価が上がった」とは読めません。

**2. 公表のタイミングが違います。**

来訪者数は2026年8月まで公表されている一方、消費動向調査は四半期公表で遅行するため2026年6月までです。**掛け合わせた試算値は、短いほうに合わせて打ち切る**必要があります。打ち切らないと、直近の月が古い四半期の単価のまま人数だけ動いた値になります。

**3. 「購入者単価」はそのままでは全体の平均ではありません。**

購入者単価は**その費目を買った人の平均額**です。買わなかった人を含めた平均にするには、**購入率を掛ける**必要があります。この一段を飛ばすと、全員が全費目を買った前提の過大な金額になります。

**4. 速報値が含まれ、後から改定されます。**

シートには `【確報】` `【2次速報】` のような**公表段階の表記**が入っています。直近の期を含む分析では、取得日を記録し、結論をその時点のものとして扱ってください。

:::

:::tip 表の構造も、期や年によって変わります

どちらのデータも、**公表のたびに形が少しずつ変わります。**

- 消費動向調査は、2026年から国籍・地域の区分が22から25に増えています（メキシコ・北欧・中東が追加）。シートの幅が48列から54列に変わる理由です
- 訪日外客統計は、年によって表の構造が4通りあります。中東地域・北欧地域の内訳行は2020年以降にしか存在せず、**2019年以前はその列自体がありません**

「全シート同じ構造」と決めつけて処理すると、ある年から静かに列がずれます。[Excel解析のページ](./parserawdata.md)で、AI がこの違いをどう見つけたかを扱います。

:::

:::tip 合計行と内訳行が同じ列に並んでいます

どちらのデータにも、**集計行が個別の国・地域と同じ列に混在**しています。

- 消費動向調査：`全国籍・地域`（全体計）、`中東`・`北欧`（地域計）、`その他`（残余）
- 訪日外客統計：`総数`、`アジア計`、`ヨーロッパ計`、および `中東地域` の内訳（イスラエル・トルコ・GCC6か国）

そのまま合計すると、**同じ取引を二重に数える**ことになります。[データ結合のページ](./joindata.md)で、これらをどう除外したかを扱います。

:::

## 本事例の進め方

本事例は、次の手順で進めます。

1. [観光庁・JNTOのWebページから、分析のための必要データを取得する](./retrievedata.md)
2. [Kari の「AI解析」機能を活用してExcelファイルの解析を自動化させる](./parserawdata.md)
3. [AI によりデータの結合処理、ファクトテーブルの作成を自動化させる](./joindata.md)
4. [国籍・地域別でインバウンド来訪者数トレンドの可視化と示唆出しを自動化させる](./visittrend.md)
5. [国籍・地域別で消費総額試算値のトレンドの可視化と示唆出しを自動化させる](./consumptiontrend.md)

手順1から3が**分析の準備**、手順4と5が**分析そのもの**です。準備に3ページを費やしているのは、**複数の出所にまたがるデータ分析では、そこが仕事の大半を占める**からです。

:::caution

**本事例で算出する消費総額は「試算値」です。** 標本調査である消費動向調査の購入者単価・購入率に、訪日外客統計の来訪者数を掛けて求めたものであり、観光庁が公表する消費額とは一致しません。

また、AI が導き出した市場動向の解釈や示唆について、本サイトはその因果関係や背景を検証していません。事業上の判断に用いる場合は、**必ず一次資料および他の情報源と照合してください。** 各ページの「Human-in-the-loop のポイント」に、確認すべき箇所を記載しています。

:::
