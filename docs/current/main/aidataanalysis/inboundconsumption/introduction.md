# 概要

## ユースケースの説明

ビジネスの現場で知りたい数字は、**1つのファイルの中に揃っていないことがほとんど**です。必要な情報は複数のデータソースがそれぞれの都合で公表しており、粒度も形式も公表のタイミングも違います。

本事例で扱う**国籍・地域別のインバウンド消費総額**は、単価と人数を別々のデータソースから取ってきて、掛け合わせて**試算**します。従来の進め方では、この準備だけで大きな工数がかかります。Excel の表から数字を取り出し、粒度をそろえ、国名の表記差を吸収し、結合する——そして仮説を変えるたびに、同じ作業をやり直すことになります。

Kari の AI エージェントを活用すれば、**取得から解析、結合、試算、可視化、示唆出しまでを一貫して任せられます。** 処理はすべてデータフローとして残るため、条件を変えた再実行も短時間で済みます。本事例を通して、**複数の出所にまたがるデータ分析**がどこまで自動化できるかを確かめてください。

## シナリオ

インバウンド需要をビジネス機会として捉える立場から、**訪日外国人の消費動向**を分析します。検証する問いは、たとえば次のようなものです。

- どの国籍・地域から、どれだけの人が来ているか。その構成は変化しているか
- 1人あたりの支出額は、国籍・地域によってどう違うか
- 消費総額はどう推移しているか。**その増減を動かしているのは何か**
- 来訪者数が伸びている市場は、消費額でも伸びているか

最後の問いが、この事例の要点です。**人数と金額は、必ずしも同じ方向に動きません。** 来訪者数だけを見て市場を評価すると、判断を誤ります。

## 扱うデータの性質

本事例では、**3つのデータソースが公表する、性質の異なるデータ**を結合します。分析を始める前に、それぞれが何であるかを押さえてください。

| | インバウンド消費動向調査 | 訪日外客統計 | 出入国管理統計 |
| --- | --- | --- | --- |
| 公表元 | 観光庁（国土交通省） | 日本政府観光局（JNTO） | 法務省（出入国在留管理庁） |
| 何を表すか | 訪日客が**1人いくら使ったか** | 訪日客が**何人来たか** | うち**クルーズ客が何人か** |
| データの性格 | **調査（アンケート）の集計** | 出入国の統計 | 上陸許可の件数 |
| 公表の粒度 | **四半期** | **月** | **月** |
| 公表のタイミング | 遅い（四半期ごと、速報→確報） | 早い（翌月） | 月ごと |
| ファイルの形 | 期ごとに別ファイル | 1ファイルに年別シート | 月ごとに別ファイル |

## 本事例の進め方

本事例は、次の手順で進めます。

1. [観光庁・JNTO・法務省のWebページから、分析のための必要データを取得する](./retrievedata.md)
2. [Kari の「AI解析」機能を活用してExcelファイルの解析を自動化させる](./parserawdata.md)
3. [AI によりデータの結合処理、ファクトテーブルの作成を自動化させる](./joindata.md)
4. [国籍・地域別でインバウンド来訪者数トレンドの可視化と示唆出しを自動化させる](./visittrend.md)
5. [国籍・地域別で消費総額試算値のトレンドの可視化と示唆出しを自動化させる](./consumptiontrend.md)

手順1から3が**分析の準備**、手順4と5が**分析そのもの**です。準備に3ページを費やしているのは、**複数の出所にまたがるデータ分析では、そこが仕事の大半を占める**からです。

試算の式は次のとおりです。手順3でこの形のファクトテーブルを作り、手順5で消費総額を求めます。

```
一般客数[国, 月]      ＝ JNTO 訪日外客数[国, 月] − クルーズ客[国, 月]
1人あたり旅行支出[国]  ＝ 参考2「全体」[国, 四半期]
消費総額試算値[国, 月] ＝ 1人あたり旅行支出[国, その月の属する四半期] × 一般客数[国, 月]
```


## 参考情報

### なぜクルーズ客の統計データが必要か

観光庁が国籍・地域別に公表している1人あたり旅行支出は、**クルーズ客を除いた「一般客」**のものです。一方、JNTO の訪日外客数には**クルーズ客が含まれます**。したがって、下記のような計算が必要です。

```
一般客数 ＝ JNTO 訪日外客数 − 船舶観光上陸許可（クルーズ客）
```

クルーズ客数は法務省の出入国管理統計から取得します。観光庁もこの統計を用いてクルーズ客数を推計していると注記しています。


### データ処理にあたっての留意事項

:::caution 分析の前に押さえておきたいこと

**1. 粒度が違うものを掛け合わせています。**

消費動向調査は四半期、訪日外客統計とクルーズ客は月です。本事例では、**四半期の単価を同じ四半期の各月に複製**して結合しています。そのため、**消費総額試算値の月ごとの変動は、人数の変動のみに由来します。** 「この月に単価が上がった」とは読めません。

**2. 公表のタイミングが違います。**

来訪者数は2026年8月まで公表されている一方、消費動向調査は四半期公表で遅行するため2026年6月までです。**掛け合わせた試算値は、短いほうに合わせて打ち切る**必要があります。打ち切らないと、直近の月が古い四半期の単価のまま人数だけ動いた値になります。

**3. 似た名前のシートで、値が1割違います。**

消費動向調査のブックには37枚のシートがあり、1人あたり支出を載せた表が複数あります。**どれを使うかで結果が変わります。**

| シート | 内容 | 2026年4-6月期の全国籍 |
| --- | --- | --- |
| `表3-1` | パッケージツアー参加費の国内分を**含まない** | 222,119円 |
| `参考2` | パッケージツアー参加費内訳を**含む** | **244,733円** |

観光庁の公表する消費総額が立脚しているのは `参考2` の系列です。本事例でもこちらを使います。

**4. 速報値が含まれ、後から改定されます。**

シートには `【確報】` `【2次速報】` のような**公表段階の表記**が入っています。直近の期を含む分析では、取得日を記録し、結論をその時点のものとして扱ってください。


**5. 表の構造も、期や年によって変わります。**

どのデータも、公表のたびに形が少しずつ変わります。

- 消費動向調査は、2026年から国籍・地域の区分が21から24に増えています（メキシコ・北欧・中東が追加）。シートの幅が48列から54列に変わる理由です
- 訪日外客統計は、年によって表の構造が4通りあります。中東地域・北欧地域の内訳行は2020年以降にしか存在せず、**2019年以前はその列自体がありません**
- 出入国管理統計は、**掲載される港が月によって変わります**

「全シート同じ構造」と決めつけて処理すると、ある年から静かに列がずれます。[Excel解析のページ](./parserawdata.md)で、AI がこの違いをどう見つけたかを扱います。



**6. 合計行と内訳行が同じ列に並んでいます。**

どのデータにも、集計行が個別の国・地域と同じ列に混在しています。

- 消費動向調査：`全国籍・地域`（全体計）、`中東`・`北欧`（地域計）、`その他`（残余）
- 訪日外客統計：`総数`、`アジア計`、`ヨーロッパ計`、および `中東地域` の内訳（イスラエル・トルコ・GCC6か国）
- 出入国管理統計：`総数`、`アジア`、`ヨーロッパ`

そのまま合計すると、**同じ人を二重に数える**ことになります。[データ結合のページ](./joindata.md)で、これらをどう除外したかを扱います。


**7. 表記もデータソースによって違います。**

同じ項目でも、データソースによって表記が異なります。データ処理でこれを考慮し正しく紐づける必要があります。

| | JNTO | 出入国管理統計 |
| --- | --- | --- |
| 香港 | `香港` | `中国〔香港〕` |

この対応付けは[データ結合のページ](./joindata.md)で扱います。

:::



:::caution 本事例は「例示」です

**本事例は Kari の動作を示す例示であり、算出される数値は観光庁の公表数値と異なる可能性があります。**

消費総額は標本調査の単価に人数を掛けて求めた**試算値**です。また、国籍・地域別の一般客数は「JNTO の人数 − 法務省の人数」で求めた近似であり、観光庁の推計と一致する保証はありません。

AI が導き出した市場動向の解釈や示唆について、本サイトはその因果関係や背景を検証していません。事業上の判断に用いる場合は、**必ず一次資料および他の情報源と照合してください。** 各ページの「Human-in-the-loop のポイント」に、確認すべき箇所を記載しています。

:::
